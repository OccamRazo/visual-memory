## 第 02 页｜路线一：压缩 token 记忆

### 上屏文字

**保存什么**

将长历史变成短潜序列 $Z\in\mathbb R^{m\times d}$。读取器把这些向量作为输入 token，再进行编码、重建或回答。

**写入设计**

先按片段得到特征，再通过池化、合并或可学习查询压缩；如果同时输入旧 token，就是递归写入。核心变量是 token 数量、维度和可见历史范围。

**读取与训练**

将潜 token 投影到读取器的嵌入空间；直接答用任务损失，先重建用重建损失，也可蒸馏长历史 teacher。压缩器与读取器是否共同训练，会影响接口适配。

$$
Z=C_\phi(H),\qquad U=[P_\psi(Z);E(q)],\qquad \hat y=D_\theta(U).
$$

**同类实现**

MovieChat 做 token 合并，VideoLLaMB 递归传递 token，LCLM 联合训练读写接口，Mem-W 用共享压缩器处理不同来源。

### 备注与来源（不上屏）

公式为本稿的接口抽象。$H$ 为历史特征，$m$ 为潜 token 数，$d$ 为向量维度，$P$ 为投影，$E(q)$ 为问题嵌入。NextMem 的潜序列可以先送入重建器恢复文本；EvoEmbedding 则把潜 token 用在检索编码器中。两者的使用者不同，但不改变 token 载体。

递归只说明 $C$ 是否还接收旧状态，不意味着必须使用关联矩阵。FlashMem 读取既有 KV 来构建潜 token，因此其主要记忆接口也放在本类。若每段各保留 $m$ 个 token，整段历史的总存储仍可能增长。

来源：[LCLM §3–4](https://arxiv.org/html/2606.09659v1)、[Mem-W](https://arxiv.org/html/2605.09317v1)、[NextMem](https://arxiv.org/html/2603.15634v1)、[VideoLLaMB](https://arxiv.org/abs/2409.01071)、[MovieChat](https://arxiv.org/abs/2307.16449)。

## 第 03 页｜代表设计：Mem-W 的共享压缩器

### 上屏文字

**1. 编码观察—动作段**

冻结编码器处理观察与结构化动作。完成的经验带成功／失败标记，本轮未结束片段使用未知标记，得到上下文化特征 $H$。

**2. 固定查询形成压缩瓶颈**

$K$ 个可学习查询通过 Q-Former 读取 $H$，再投影成 $K\times d$ 潜 token；跨任务经验与本轮过期历史共用这个压缩器。

$$
Z=P_\phi\!\left(\operatorname{QFormer}_\phi(Q,H)\right),\qquad Q\in\mathbb R^{K\times h}.
$$

**3. 组装输入并训练接口**

检索经验的潜 token、本轮历史的潜 token、当前画面及近期原始步骤组成 agent 输入。冻结 agent，先用长历史 teacher 自蒸馏，再按任务结果训练压缩器。

**设计要点**

共享的是 token 读写接口，来源可不同；离散 Top-M 检索并未因此变成可微。完整轨迹库仍需计入存储。

### 备注与来源（不上屏）

Mem-W: Latent Memory-Native GUI Agents，2026-05，LV-NUS Lab（NUS／NTU、Guibin Zhang、Shuicheng Yan）。GUI 是应用标签，本页介绍的是共享查询压缩器与输入嵌入接口。

公式省略结果嵌入和段落边界；原文在编码特征及查询中引入结果信息，并保留当前原始上下文。自蒸馏使用动作监督与 teacher/student 分布对齐，后续结果优化仍只训练压缩器。原文双来源消融支持两种记忆互补，但不保证精确事实可重建。

同一技术家族中，L²-VMAS 分开视觉和思考来源，LaMem-VLA 将 token 给动作策略读取；它们应比较压缩条件和注入位置，而非按任务另立类别。

来源：[Mem-W §3.2–3.4、§4.4](https://arxiv.org/html/2605.09317v1)、[L²-VMAS](https://arxiv.org/html/2602.00471v2)、[LaMem-VLA](https://arxiv.org/html/2607.07608v1)。

## 第 04 页｜路线二：KV 缓存记忆

### 上屏文字

**保存什么**

保存历史经过模型后的各层键值 $K_\ell,V_\ell$。新问题在对应注意力层直接读取，不必重新编码历史 token。

**写入与压缩设计**

新片段增量预填充产生 KV；超过预算后逐层选择、合并或生成摘要 KV。保留分数可来自时间、注意力、频率或扰动敏感性。

**读取与一致性设计**

缓存需要维护层号、位置和可见范围。跨层淘汰要避免内容错位；重新排列缓存要处理位置编码；外部 KV 还需检索与搬运。

$$
o_\ell=\operatorname{softmax}\!\left(\frac{q_\ell K_\ell^{\top}}{\sqrt{d_k}}\right)V_\ell.
$$

**同类实现**

ReKV 检索外部缓存，StreamMem 做问题无关选择，HERMES 做跨层管理。IndexMem 另加关联状态，是 KV＋矩阵的混合。

### 备注与来源（不上屏）

式中 K/V 指经过方法选择或压缩后的记忆缓存。普通 Transformer 临时生成 KV 不构成独立记忆设计。Video-XL 的总结 token 最终保留层内 KV，应放在本类；MuKV、OmniMem 的区别是管理粒度和预算依据。

T1 token 和 T2 KV 并非完全独立的数据类型：token 经过模型会形成 KV。分类看被长期保存、供后续调用的对象。存一组输入向量，与存每层多头 K/V 的字节数和读取成本不同。

来源：[ReKV](https://arxiv.org/abs/2503.00540)、[StreamMem](https://arxiv.org/html/2508.15717)、[HERMES §3](https://arxiv.org/pdf/2601.14724)、[Video-XL](https://arxiv.org/abs/2409.14485)、[IndexMem](https://arxiv.org/html/2605.25475v2)。

## 第 05 页｜代表设计：HERMES 的逐层缓存管理

### 上屏文字

**1. 按层生成重要性分数**

浅层以时间衰减强调近期信息，深层用注意力保留稳定锚点，中层混合二者。真实问题未知时，用通用提示估计注意力重要性。

**2. 平滑分数再选择 KV**

将深层的重要性传到浅层，缓解同一内容在各层被独立淘汰造成的不一致；各层按预算保留高分 K/V，并聚合淘汰内容为摘要 KV。

**3. 维护位置并直接回答**

接近位置上限时才重索引是 lazy 策略，每次压缩都重索引是 eager 策略。问题到来后直接读取已维护好的缓存，无需再做视频检索或压缩。

**训练与验证**

策略免训练；分别检验层次评分、跨层平滑及位置处理。技术重点是缓存管理，长期事实保持仍要用具体问题评测。

### 备注与来源（不上屏）

HERMES: KV Cache as Hierarchical Memory for Efficient Streaming Video Understanding，2026-01，复旦 OpenMOSS、上海创智、NUS。原文跨层平滑为相邻层分数的加权融合，而非所有层强制选同一组条目。

原文实现用不同深度比例分区，并提供 1D RoPE 与 3D M-RoPE 的位置处理。这里不将其配置比例写成一般原则。所谓“问题到来后无需额外计算”，指无需额外的视频检索／压缩过程；正常的问题预填充、注意力和解码计算仍存在。

论文评测包含流式及离线视频。收益来自分层保留、平滑、摘要和位置维护的组合，不能只归结为“有长期记忆”。

来源：[HERMES §3.1–3.3、§4.1](https://arxiv.org/pdf/2601.14724)、[官方项目](https://hermes-streaming.github.io/)。

## 第 06 页｜路线三：关联矩阵记忆

### 上屏文字

**保存什么**

用固定维矩阵 $S\in\mathbb R^{d_v\times d_k}$ 保存键值关联。查询通过 $r=Sq$ 读出，历史不再以逐 token K/V 列表存在。

**写入设计**

当前隐藏状态投影为键 $k$ 与值 $v$。外积写入累积 $vk^\top$；delta rule 先预测 $Sk$，再写入预测误差，减少无选择累积。

$$
S_t=\lambda S_{t-1}+\eta\bigl(v_t-S_{t-1}k_t\bigr)k_t^{\top}.
$$

**读取与学习设计**

读出可加入残差，也可修正注意力。投影与门控由训练学习；交互时更新状态，基础模型权重可以保持冻结。

**关键变量**

矩阵维度、键的可分离性、遗忘／写入门和读写次序。递归 token 属于路线一，不能仅因“递归”就归入本类。

### 备注与来源（不上屏）

公式为标量门控 delta-rule 示意，采用列向量约定：$k,q\in\mathbb R^{d_k}$，$v\in\mathbb R^{d_v}$。实际方法可使用逐维门控、归一化、分头与分块更新。下一页给 δ-mem 的逐维形式。

关联矩阵有时被称为 fast weights。分类看运行时是否作为历史关联状态更新和查询，不能只看作者用了 state 还是 parameter 这个词。Metis 的动态矩阵、δ-mem 的小型关联状态、RetentiveKV 的 SSM 状态均可在这个技术维度比较。

来源：[δ-mem §2–3](https://arxiv.org/html/2605.12357v1)、[Metis §3](https://arxiv.org/html/2607.26760v2)、[RetentiveKV](https://arxiv.org/html/2605.04075v1)。

## 第 07 页｜代表设计：δ-mem 的读—调节—写

### 上屏文字

**1. 从旧状态读取**

冻结骨干，将当前隐藏状态投影为记忆查询；以 $r_t=S_{t-1}q_t$ 读取历史关联，不返回文本，也不添加记忆 token。

**2. 调节当前注意力**

将 $r_t$ 分别投影成查询修正和输出修正：前者改变注意力的查询，后者补充注意力结果。同一输入可因历史状态不同产生不同修正。

**3. 按预测误差写回**

计算当前键的旧预测 $S_{t-1}k_t$，再用逐维保留门 $\lambda_t$ 和写入门 $\beta_t$ 更新：

$$
S_t=\operatorname{Diag}(\lambda_t)S_{t-1}
+\operatorname{Diag}(\beta_t)(v_t-S_{t-1}k_t)k_t^{\top}.
$$

**学习方式**

先将历史写入状态，预测时不再重放历史文本；冻结骨干，用回答交叉熵训练记忆模块，促使回答利用状态通道。

### 备注与来源（不上屏）

δ-mem: Efficient Online Memory for Large Language Models，2026-05，NTU／DeCLaRe Lab、Mind Lab、复旦、上海交大等。为统一符号，省略原文记忆查询、键、值的上标 m；更新式对应原文 Eq.10。

该式可拆成“保留旧状态－擦除当前键方向的旧预测＋写入目标值”。两个修正投影训练后保持固定，但它们读取的动态状态会改变。原文以记忆任务和通用能力作区分评估；小状态的实验配置不代表整个系统只有这点内存，普通查询 KV 和新增模块权重仍占空间。

来源：[δ-mem §3.1–3.6、§4–5](https://arxiv.org/html/2605.12357v1)。

## 第 08 页｜路线四：条件查表记忆

### 上屏文字

**保存什么**

将离散模式映射到潜向量表。运行时根据地址读取少量表项，再将结果融合进模型，不需要从实例库中做语义近邻搜索。

**地址与值的设计**

地址可由规范化 n-gram 和哈希形成；值可以在预训练中学习，也可以由冻结模型离线生成。地址冲突、未命中和表容量是主要设计变量。

$$
a_t=\operatorname{Address}(x_{t-n+1:t}),\qquad e_t=E[a_t].
$$

**读取设计**

查出的向量提供静态模式，当前隐藏状态通过投影与门控决定注入多少。相同地址读到相同向量，使用强度仍可随上下文变化。

**同类实现**

Engram 学习哈希向量表；Memory Grafting 用大模型离线表征构表。它们扩展知识查找能力，不自动写入新的会话经历。

### 备注与来源（不上屏）

T4 的核心算子是离散寻址后的 gather／lookup。虽然 embedding 表可训练，仍应区别于 T5 通过参数增量修改模型的前向映射。纯粹因为向量表“也是参数”而合并两者，会丢失查表和计算调制的技术差异。

这条路线的总存储随表容量决定；一次只查少量表项不意味着整个库很小。确定性地址有利于预取，但仍需要核算 CPU／GPU 放置和带宽。

来源：[Engram §2](https://arxiv.org/html/2601.07372v2)、[Memory Grafting §3](https://arxiv.org/html/2605.20948v1)。

## 第 09 页｜代表设计：Engram 的多头查表与门控

### 上屏文字

**1. 规范化模式，构造多个地址**

将原始 token ID 映射为规范化 ID，再为不同 n-gram 阶数配置多组哈希；每个头读取对应表项，多头结果拼接成记忆向量。

$$
e_t=\operatorname{Concat}_{n,k}\;E_{n,k}\!\left[\operatorname{Hash}_{n,k}(g_{t,n})\right].
$$

**2. 结合当前上下文消歧**

记忆向量投影为键和值，当前隐藏状态作查询；经归一化相似度得到门值，抑制不匹配内容，再通过短因果卷积和残差融合。

**3. 训练表值，推理时读取**

向量表在预训练中学习，运行时按局部模式寻址。可以扩大表容量并预取表项，但不把新观察自动变成持久事实。

**验证重点**

比较相同参数／计算预算下的查表与神经计算分配，同时检查地址冲突、门控和带宽开销。

### 备注与来源（不上屏）

Engram: Conditional Memory via Scalable Lookup，2026-01，DeepSeek-AI、北京大学。$n$ 为 n-gram 阶数，$k$ 为哈希头，$g_{t,n}$ 为当前规范化后缀；公式概括原文多头查询与拼接。

多头哈希缓解单一地址碰撞，无法保证完全无碰撞。门控也不是事实正确率判断器；它利用当前隐藏状态与被检索模式的匹配程度调节注入。原文还研究容量与计算的分配；本页强调查表构件，不用它的模型规模推断视频实例记忆容量。

来源：[Engram §2.2–2.5、§3–4](https://arxiv.org/html/2601.07372v2)。

## 第 10 页｜路线五：参数记忆

### 上屏文字

**保存什么**

将上下文效应写进可调用的参数增量 $\Delta\theta_i$。读取时使用修改后的模型映射，而非增加记忆 token 或查询历史状态矩阵。

**写入设计**

先从上下文构造监督或 teacher 分布，再冻结基础模型、只优化小模块。独立模块可减少多份上下文混写，但会增加管理和存储成本。

$$
W_i'=W+A_iB_i,\qquad \operatorname{rank}(A_iB_i)\leq r.
$$

**读取与管理设计**

建立上下文到模块的索引；查询时检索候选、选择模块、判断是否启用。更新、撤销和过期都需要在模块层处理。

**核心取舍**

重复读取可能更省上下文，但写入需要优化。应分别报告每份上下文的训练成本和非 oracle 检索时的任务效果。

### 备注与来源（不上屏）

式中 $A_i\in\mathbb R^{d_{out}\times r}$、$B_i\in\mathbb R^{r\times d_{in}}$ 为 LoRA 因子。这里以模块化参数记忆为当前文献代表，不将所有普通模型微调都自动视为实例记忆系统。

与 T3 的关键区别是更新与读取协议：T3 运行时按历史键值关系递归更新状态，再以 $Sq$ 查询；这里通过优化形成模块，调用 $f_{\theta+\Delta\theta_i}$ 改变前向映射。参数记忆也可与外部检索组合，检索器本身不是另一种参数存储机制。

来源：[Context Distillation §2–3](https://arxiv.org/html/2605.28889v1)。

## 第 11 页｜代表设计：独立 LoRA 的写入与调用

### 上屏文字

**1. 将每份上下文蒸馏成一个模块**

teacher 显式读取上下文 $c_i$；student 使用查询和独立 LoRA，匹配 teacher 的输出分布，把上下文效应写入 $\Delta\theta_i$。

**2. 专门训练缓存兼容性**

基础模型计算查询前缀 KV，候选模块接着生成；训练时就采用这一接口，使多个模块可复用前缀。任意 LoRA 并非天然支持这种切换。

**3. 分开完成检索、路由与启用**

外部 embedding 找候选；内部路由结合相关度、首 token 隐藏状态及熵选择模块；再以熵门控决定继续使用或退回基础模型。

**验证重点**

分别检查单模块是否学会、检索是否选对、错误模块是否伤害回答，以及写入／存储／调用总成本。

### 备注与来源（不上屏）

Context Distillation as Latent Memory Management，2026-05，CUHK（Qiang Xu）、华为诺亚方舟实验室。原文以 KL 对齐 teacher 与 student；teacher 也可复用同一上下文的缓存。student 的 cache-sharing 是有意识构造的训练分布，不应省略成泛化的“LoRA 热插拔”。
