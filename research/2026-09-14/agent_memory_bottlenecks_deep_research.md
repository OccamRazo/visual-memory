# Agent 记忆系统的核心瓶颈

## 核心判断

**当前 Agent 记忆最根本的问题，是在有限资源、信息不断变化、未来任务尚不完全已知的条件下，无法稳定地把经历转化为对后续决策有用、可信、可更新的状态。** 存下信息、找到相关内容、回答历史问题，分别只是这项能力的一部分。真正的检验是：经历增加以后，Agent 是否更少重复错误、更准确地遵守约束，并在环境变化后及时修正行动。

这是对现有证据的综合判断，并非已有统一实验确认的“全行业最大故障”。不同场景的首要故障会不同：个人助手常遇到偏好更新和时间冲突，代码 Agent 常丢失约束与失败诊断，持续视觉 Agent 则必须在观察当时决定保留什么。贯穿这些场景的是同一个问题：**记忆的组织和使用尚未充分围绕未来任务收益来优化。**

研究范围截至 2026 年 9 月 14 日，以公开论文、原始评测和方法作者的一手材料为依据，重点覆盖 2025—2026 年工作。讨论以具有持久状态的 LLM Agent 为主，兼顾模型内部记忆与视觉场景。文中将论文结果、分析推论与研究建议分开；最新预印本用于辨认方向，不等同于成熟共识。

| 判断层次 | 最突出的问题 | 对研究的含义 |
| --- | --- | --- |
| 根本机制 | 写入、保留、修正和调用，不能稳定服务于未来决策 | 应研究任务收益如何反馈到记忆策略 |
| 直接可靠性 | 过期状态、错误推断、遗漏证据持续影响后续行为 | 应检验时间有效性、来源、撤回与错误恢复 |
| 研究方法 | 问答成绩与持续行动收益之间缺少充分对应 | 应结合组件诊断与任务闭环，控制模型和成本 |
| 部署约束 | 写入和维护开销、响应延迟、存储增长相互制约 | 应比较完整生命周期，而非只比较查询速度 |

## 1. 首先明确：什么才算解决了记忆问题

本报告将记忆理解为一个动态过程：Agent 从观察、行动与反馈中维护状态，再利用该状态回答问题或选择行动。可以简写为：

\[
M_{t+1}=U(M_t,o_t,a_t,f_t),\qquad
c_t=R(M_t,q_t,g_t),\qquad
a_{t+1}\sim\pi(o_{t+1},g_t,c_t).
\]

其中，观察是 \(o\)，行动是 \(a\)，反馈是 \(f\)，任务目标是 \(g\)，记忆状态是 \(M\)，送入决策模型的记忆上下文是 \(c\)。这里的更新函数既可以是规则，也可以是 LLM 控制器、神经网络或测试时学习过程。这是分析框架，不是某篇论文的具体算法。

需要分开四种常被混称为“记忆”的东西。

| 层次 | 典型载体 | 主要作用 | 单独具备它还不能证明什么 |
| --- | --- | --- | --- |
| 当前工作上下文 | 提示词、近期轨迹、KV cache | 支持本轮推理与生成 | 跨会话持久性、事实有效性 |
| 历史证据 | 消息、截图、日志、事件记录 | 保留可追溯的经历 | 能自动推断当前状态 |
| 语义和状态记忆 | 用户偏好、实体关系、当前任务状态 | 表达目前相信什么 | 能处理所有冲突与变化 |
| 程序和经验记忆 | 工作流程、失败教训、可执行技能 | 改善未来行动 | 能在新环境中正确泛化 |

近年的综述已从形式、功能和动态过程等维度整理 Agent 记忆；因此，仅沿“短期／长期”二分法讨论，容易把不同问题混在一起。[^1] 例如，增加 KV cache 容量可以延长可访问历史，却没有自动规定如何撤回错误结论；建设一个外部数据库，也没有自动教会 Agent 何时调用它。

评估成功与否，至少要同时追问三件事：证据是否还在；对证据的解释是否仍有效；它是否在需要时影响了行为。后文的瓶颈分别发生在这些环节之间。

## 2. 最基础的难点：写入时不知道未来会需要什么

### 2.1 保存“显著信息”与保存“未来有用信息”不同

写入策略常能识别人名、日期、反复出现的偏好、显著事件和当前任务要点。但未来任务可能依赖一次不起眼的观察：某个操作失败时的状态、一个物体的短暂移动、一个决定只适用于特定版本的前提。压缩时删掉这些内容，后续更强的检索器也无法从已删除的证据中恢复它们。

困难在于收益通常延后出现。今天保存一个字段的价值，可能要到明天执行新任务时才能知道。即使未来任务失败，也难以判断原因究竟是证据没写入、检索没找到、模型没理解，还是行动本身出错。这构成了记忆管理的信用分配问题。

AgeMem 已经把存储、检索、更新、摘要与丢弃作为可学习的操作，并用渐进式强化学习处理稀疏奖励。[^12] 这说明“学习记忆策略”已有明确技术基础；目前更值得问的是，在不同任务分布、较长时间跨度和固定预算下，学到的策略能否可靠迁移。

2026 年的多因素记忆价值研究还明确指出：如果在决定保留内容时使用测试问题的相似度，就把未来信息提前交给了写入策略。其对照区分了知道问题的选择与不知道问题的保留。[^17] 这项研究主要度量证据保留，不能据此宣称它已解决持续任务执行，但它揭示了实验中必须防止的信息泄漏。

### 2.2 价值可能属于一组证据

以下是说明机制的构造例子，并非论文数据：

- 早上：一个人把钥匙放进蓝包。
- 中午：另一个人将蓝包里的钥匙移到抽屉。
- 下午：蓝包被拿走。

若问题是“钥匙现在在哪里”，仅保存最显著的“蓝包被拿走”会误导回答。第一、第二条的对象对应关系与动作顺序共同决定答案。在其他任务中，单独看都不重要的两条记录，也可能共同构成一条必要的因果链或排除条件。

由此得到的分析推论是：逐条独立打分容易遗漏互补性。一个记忆项的价值应当与已经保留的其他内容、可能的未来任务、错误后果和重新获取成本有关。图结构可以表达关系，却不自动解决应保留哪些关系的问题。

### 2.3 有限记忆必然需要明确取舍

如果允许未来问题询问历史中的任意细节，那么对一般无限增长的历史，固定大小状态不可能无损区分所有情况。因此，实际可研究的目标应当是：在指定任务分布和成本约束下，尽量减少与决策有关的信息损失。

一个可操作的目标可以写成：

\[
\min_{U,R,\pi}\;\mathbb E[\mathcal L_{\mathrm{task}}]
+\lambda_w C_{\mathrm{write}}+\lambda_r C_{\mathrm{read}},
\quad \text{s.t. } \mathrm{Bytes}(M_t)\le B.
\]

这里的损失应来自未来问答或行动，而非仅来自摘要相似度。它是本报告提出的研究目标，不是已被实验证明最优的训练方法。若研究特别重视罕见而昂贵的错误，还应另外检验尾部风险，避免平均分掩盖关键证据的丢失。

## 3. 最直接的可靠性问题：记忆会过期、被误解，也会被污染

### 3.1 “新的覆盖旧的”只适合部分任务

新的消息可能描述过去，也可能只是转述、假设、计划，或者对旧事实的修正。接收到信息的时间，不一定等于事实发生或生效的时间。世界发生变化与先前认识被纠正，也需要不同的处理。

例如，“我三月份搬到了杭州”和“上次说搬家是计划，实际没有搬”应产生不同的状态变更。可靠系统应保留足够的时间和来源信息，判断当前状态与历史状态分别是什么，并允许承认无法确定。

Zep 的双时间建模区分事件时间与信息摄入时间，并通过关系有效期处理更新。[^9] Hindsight 将外部事实、自身经历、意见和综合观察分开管理。[^10] 这些机制已经触及问题核心，但表示中存在字段，不等于模型能够始终正确抽取时间、识别同一实体或判断证据冲突。

MemoryAgentBench 的 FactConsolidation 则用有序的新旧事实检验冲突后的推理。在论文报告的多跳选择性遗忘设置中，所测方法最高准确率仍不超过 28%。这个结果说明**该设置下的版本选择与关系组合很难**，不能解释成当前所有系统的通用能力上限，也不能把正确回答等同于物理删除成功。[^3]

### 3.2 遗忘至少有三种含义

| 操作 | 实际含义 | 可验证方式 |
| --- | --- | --- |
| 本次不使用 | 查询时排除无关或过期内容 | 当前问题是否仍被旧内容干扰 |
| 逻辑失效 | 记录保留，但不再代表当前状态 | 当前与历史查询是否分别正确 |
| 物理删除 | 记录及规定范围内的派生副本被移除 | 检查原文、索引、摘要和备份等对应存储 |

9 月 9 日发布的 RD-Forget 明确保留原始档案，再构造与当前问题相关的记忆视图；被新事实取代的信息仍可用于历史问题。[^16] 这提供了有意义的语义区分。但是，当原始档案完整保留时，其结果并不证明已经解决固定总存储下的不可逆遗忘。

这一边界对视觉研究尤其重要：只减少送入模型的视觉 token，而在后台无限保留原视频，研究的是受限读取；若声称研究有限记忆，则还必须说明原视频、关键帧、向量、摘要与索引能保留多少。

### 3.3 一次错误可以跨多轮传播

以下是分析得到的典型链条：错误观察或推断被写成事实，摘要时失去来源和不确定性，后来被检索为历史依据，最后又被新的总结重复。重复次数增加，并不意味着独立证据增加。类似地，一条来自网页或工具输出的指令，即使进入了持久记忆，也不应获得更高的操作权限。

MINJA 已展示攻击者通过交互使恶意记录进入 Agent 记忆、继而影响后续请求的可能性。[^14] 后续在 EHR Agent 上的研究发现，既有正常记忆等条件会明显改变攻击效果。[^15] 因此，风险机制有直接证据，但不能将某个攻击实验的成功率外推为真实部署中的普遍发生率。

工程上的关键要求应落到可检查的行为：区分观察与推断，记录来源，标记适用范围；对错误结论执行撤回时，追踪依赖它的摘要和策略。后者是本报告建议的验证目标，现有文献尚不足以说明多数系统已经做到可靠的跨层撤回。

## 4. 对 Agent 最关键的断点：记得，却没有在行动时用对

### 4.1 回答历史问题与完成任务需要不同的调用方式

问答通常直接提示需要什么，例如“用户上次说预算是多少”。行动任务则可能只是“帮我安排这次行程”，Agent 必须自己意识到预算、时间、同行者约束与旧决定都应参与规划。检索查询如何生成、在什么时刻调用、返回哪些约束，都是问题的一部分。

Mem2ActBench 专门评测长期记忆能否用于工具选择与参数填充，包含 400 个工具任务；其结果指出，七种被测记忆框架在主动将记忆落实到参数上仍有不足。[^23] 它比纯历史问答更接近动作使用，但仍不能覆盖长期开放环境中的全部行动后果。

MemoryArena 将记忆置于相互依赖的多会话任务中。论文观察到外部记忆并非在所有任务上都有收益，且随着依赖深度增加，各种方法仍出现性能下降。[^4] 这支持“召回能力不能替代行动验证”的判断；但最终任务失败同时受到规划、工具调用和推理能力影响，不能全部归因于记忆。

### 4.2 内容进入上下文，也不保证持续约束行为

2026 年 7 月的 Proactive Memory Agent 研究把“任务状态不再影响下一步行为”作为单独问题。它在保持行动 Agent 不变的情况下，加入维护状态并选择是否提醒的记忆模块。[^20]

| 论文中的设置 | 基线 pass@1 | 加入记忆模块 | 差值 |
| --- | ---: | ---: | ---: |
| Terminal-Bench 2.0，Sonnet 4.5 行动模型 | 37.6% | 45.9% | +8.3 个百分点 |
| τ²-Bench，Sonnet 4.5 行动模型 | 55.0% | 61.8% | +6.8 个百分点 |

上述配置使用 Opus 4.6 作为记忆模型。论文还比较了被动暴露记忆、始终提醒和其他变体。**收益同时伴随额外模型能力和计算开销**，不能视为纯粹增加存储带来的效果，也不能外推为跨月记忆已解决。其最重要的启发是，应直接研究什么时候让记忆介入行动。[^20]

### 4.3 从经验中学到什么，也需要验证

ReasoningBank 从成功和失败经历中提炼可复用策略，使用 Agent 自己对结果的判断来组织学习，并研究更多测试时探索与记忆之间的相互促进。[^11] 这将关注点推进到了经验收益，但也留下一个重要问题：如果成功归因错了，或者只在原环境成立的教训被当作普遍规则，新的经验会不会造成负迁移？

合理的经验条目不应只有“应该怎么做”，还应说明在哪些前提下适用、依据来自哪些经历、什么时候重新检查。区分环境状态与程序经验也很重要：某按钮今天失效，可能是临时状态；某业务流程必须先授权，则可能是稳定规则。两者应有不同的保留和验证策略。

## 5. 研究层面的最大障碍：测到的未必是所声称的能力

### 5.1 不同基准回答不同的问题

| 基准或研究 | 主要提供的证据 | 不宜由它直接推出的结论 |
| --- | --- | --- |
| LongMemEval | 跨会话抽取、时间推理、更新、拒答 | Agent 能持续完成相互依赖的真实任务 |
| MemoryAgentBench | 增量摄入后的检索、学习、整合理解与冲突处理 | 原始存储已删除，或长期动态世界已被正确维护 |
| LongMemEval-V2 | 多模态网页操作经历中的证据组织与经验问答 | 同一个 Agent 已在线持续学习并成功执行这些任务 |
| Mem2ActBench | 历史信息用于工具选择和参数填充 | 开放环境中的长期执行与故障恢复已解决 |
| MemoryArena | 记忆与多会话行动之间的整体关系 | 所有性能差异均来自记忆表示 |
| EgoLifeQA | 跨日第一人称经历中的回顾性问答 | 单遍压缩或主动行动已经被评测 |

这些区别来自各基准的任务定义。[^2][^3][^4][^5][^21][^23] 一个基准不覆盖某项能力，不意味着它无用；问题出在把局部指标解释得过宽。对研究选题而言，组件诊断和闭环任务应当互补。

### 5.2 同一数据集上的高分也未必可直接比较

比较记忆方法时，至少需要对齐：基座模型、记忆控制器、读取模型、评测裁判、数据版本、可访问历史、查询预算、写入成本以及重复试验方式。否则，架构改变与模型能力、额外推理和提示策略会混在一起。

Anatomy of Agentic Memory 的实证分析显示，词面 F1 与语义裁判会给出不同排序；其表格中的两个领先方法，也会随裁判提示变化交换第一、第二。[^6] 因而，语义裁判有价值，但不能把一个裁判提示下的小幅领先当作稳健优势。更好的做法是保留逐例结果，对分歧样例进行人工核查，并报告不确定性。

8 月的 MemoryLake 对比研究明确承认：它改变的是包含写入、检索、整合和上下文组装的整套后端，不是只改变表示；各方法也未做到成本匹配。[^19] 这种边界说明比笼统宣称某种结构最好更有研究价值。需要注意，该研究部分领域样本较小，置信区间重叠，结果不能作为通用系统排名。

### 5.3 近期强基准仍有显著的质量与延迟取舍

以下只摘取 LongMemEval-V2 原论文 v1 表 2 的 Small 设置，以避免将不同长度设置混合为一个数字。其固定读取模型为 Qwen3.5-9B；不同方法家族的控制器不同。[^5]

| 记忆方法 | Overall | 查询延迟 |
| --- | ---: | ---: |
| RAG：query → slice | 42.8% | 0.1 秒 |
| AgentRunbook-R | 58.6% | 26.9 秒 |
| 通用编码 Agent（Codex） | 69.9% | 177.2 秒 |
| AgentRunbook-C | 74.9% | 108.3 秒 |

这是一组特定设置下的证据搜集与问答结果，不是线上 Agent 成功率。它表明更积极的证据处理可以提高质量，同时付出更高查询成本；跨家族差异也包含控制器能力的影响。论文固定的是返回上下文预算，不是完整存储预算。[^5]

报告不沿用该论文引言中简单 RAG 的跨设置汇总数字，因为它与表 2 两个 Overall 的简单均值并不一致。这样不会影响上述逐设置对比，但应避免继续传播口径未解释的汇总值。

## 6. 为什么更长上下文、图记忆和更强模型都只能解决一部分

### 更长上下文

更长上下文可以保留更多原始信息，在历史不大时尤其值得作为强基线。ConvoMem 的作者在其短至中等历史设置中报告，全上下文方法优于若干专门记忆系统。[^18] 与此同时，Hindsight 报告在其 LongMemEval 配置下，通过记忆系统改善同一基座的问答效果。[^10] 两者并不矛盾：数据规模、检索任务、模型和系统实现不同，收益边界也会不同。

分析上，更长上下文延缓了容量压力，却仍需决定哪些信息代表当前事实，以及哪些旧约束应该影响动作。它还需要承担读取增长历史的成本。因此它是必须认真比较的方案，而非已经消除记忆研究需求的证据。

### 图结构与自然语言摘要

Mem0 提取并整合显著信息，A-MEM 通过笔记、索引与链接动态组织记忆。[^7][^8] 图结构有助于关联实体、事件与来源，摘要有助于减少重复内容；它们解决不同侧面的问题。

但关系图中的错误关系仍是错误，摘要遗漏的条件仍然无法用于推理。复杂结构还需要维护成本。应通过预算匹配和结构消融验证图的额外收益，而不是从“信息有关系”直接推导出“图一定优于文本或混合检索”。

### 神经和参数化记忆

Titans 研究将历史压入测试时更新的神经记忆，并结合短期注意力。[^22] 这类方法为紧凑状态和学习式写入提供了另一条路线，但其序列建模或长上下文结果不能直接证明跨用户来源追踪、精确撤回或持续 Agent 经验迁移。

系统研究应允许多种载体共存：近期上下文负责即时推理，压缩状态负责概括和控制，必要的外部证据负责精确核验。是否需要这些层、怎样分配预算，仍应由任务决定。

### 更强的记忆控制器

更强模型可能改善抽取、冲突判断和检索计划，但也可能将成本集中到写入阶段。Omri 等对十种系统的分析区分了构建、检索和生成成本，指出系统设计会在不同阶段转移开销。[^13] 这解释了为什么“查询 token 更少”不足以证明整体更省。

一个基本核算方式是：总成本等于构建成本、历次维护成本与各次查询成本之和。后台运行可以隐藏部分用户等待，却不会使计算成本消失；异步构建还可能让最新观察暂时无法被查询。报告应分别记录总资源、响应时间与更新可见延迟。

## 7. 对持续视觉记忆的意义

视觉流把上述问题放大，因为内容密度高、冗余多，而关键证据可能只出现一次。下面的分析属于从 Agent 记忆研究向视觉场景的推演，不能当作这些文本系统在视频上的实验结论。

**第一，写入发生在问题到来之前。** 离线视频 QA 往往允许先知道问题再选帧；持续视觉记忆则可能必须先压缩数小时经历。两者的算法信息条件不同，应分别报告。

**第二，视觉中的“状态未变化”与“没有观察到变化”不同。** 物体离开视野后，记忆仍可保存最后位置，但当前置信程度取决于观察间隔、遮挡和环境动态。若在没有新观察的情况下始终把旧位置当作确定事实，就可能产生错误行动。

**第三，文字化可能丢失后续需要的辨识细节。** “桌上有杯子”没有保留纹理、朝向、相对位置或对象身份线索。保存原始图像也未必总是最优，因为它更占空间且需要读取计算。值得研究的是如何为不同证据保留合适的精度，并记录压缩后无法确定的内容。

**第四，状态变化需要关联身份、时间与事件。** 仅独立检索相似关键帧，可能拿到两个不同时刻的状态，却无法确定它们属于同一对象，或者中间发生了什么。更新策略应该以事件及其证据依赖为单位接受检验。

EgoLife 提供六位参与者共同生活一周、合计约 300 小时的第一人称经历，适合作为跨日视觉记忆的真实素材。[^21] 若用于研究固定预算写入，还需要另外定义时间顺序、可访问视频范围、保留量和回读成本，不能将原始回顾性 QA 协议直接称为单遍有限记忆。

与目前项目的研究主题最贴近的具体问题是：

> 在未来查询未知、总记忆受限的视觉流中，如何保留对未来决策具有互补作用的证据，并在对象状态变化时更新当前信念，同时保留必要的历史可追溯性？

这是值得验证的问题表述，不是新颖性已经确认的论文主张。“未知未来查询”“有选择的遗忘”“关系保留”“记忆介入行动”都已有相邻工作。真正的贡献必须落到新的机制或新的、严格受控的实证发现上。

## 8. 三个可检验的研究切口

以下是建议设计，尚未运行实验；建议先验证其中一个，不同时扩大为完整通用记忆系统。

### 方向一：未来问题未知时的成组证据保留

**假设：** 在相同总存储和计算预算下，考虑证据互补性的写入策略，比独立显著性打分更能保留多跳、状态变化和罕见细节问题的必要证据。

以 EgoLife 的时间流或其他可公开复现的长历史为素材，先完成写入再公布测试问题。对照至少包括均匀采样、近期优先、逐项重要性、层级摘要和一种强混合检索方法。使用未来真实问题的选择器只作为明确标记的信息上界，不能进入可部署方法组。

评价最终答案、完整证据集合保留率及不同预算下的曲线。按对象、时间段和问题模板划分测试集，并加入与训练分布不同的查询，检验策略是否只记住了常见题型。

**关键否证条件：** 如果等预算随机或简单策略已经同样好，或者收益在严格禁止未来问题泄漏后消失，就不能支持复杂选择机制。最近邻至少包括多因素记忆价值研究、RD-Forget，以及已有视觉关系和事件记忆；仅换一种重要性打分不足以构成贡献。[^16][^17]

### 方向二：状态更新与错误结论撤回

**假设：** 显式区分观察、推断、事件时间与摄入时间，并记录派生关系，可以减少状态更新后的旧事实使用和连锁错误。

从文本事实链开始构造可诊断对照，再扩展到视觉对象迁移和身份混淆。输入应包含真实变化、延迟到达的旧信息、对错误观察的更正，以及证据不足的情况。对照包括只追加、简单最新覆盖、时间图结构和带来源依赖的更新机制。

同时测试当前状态、历史状态、变化过程与拒答，避免通过永远选择最新值或永远保守拒答获得表面优势。将错误源纠正后，检查相关摘要与经验规则是否仍传播旧结论。

**关键否证条件：** 若收益只来自新增时间标签，或简单结构化数据库规则便能达到相同效果，则应把贡献限制为数据与协议发现。时间建模本身已有 Zep 等工作，不能以“加入时间字段”作为主要新颖性。[^9]

### 方向三：何时让记忆影响下一步行动

**假设：** 在有明确约束、重复失败和待完成子目标的长任务中，按风险和证据选择介入时机，可以减少错误，同时比每步注入全部记忆更节省上下文和延迟。

固定行动模型，比较无记忆、被动检索、定期摘要、始终提醒与选择性提醒。加入同等额外计算但不读历史的顾问对照，区分记忆收益与增加一个强模型的收益。观察工具参数正确率、重复失败率、约束违反率、最终任务成功与全流程成本。

**关键否证条件：** 若相同成本下的额外推理就能达到相同收益，不能将改进归因于记忆策略。Proactive Memory Agent 已直接研究这个方向，因此新的工作需要明确的场景差异、学习信号或预算约束。[^20]

这三个方向中，第一项与持续视觉压缩最贴近；第二项更容易先获得清晰的机制诊断；第三项最直接回答 Agent 是否因记忆而更可靠，但也最容易被行动模型与额外计算混淆。

## 9. 一套能定位失败原因的最小评测

应在相同样例上逐步替换组件，而不只比较最终总分。下表中的 oracle 指评测时提供已知正确的证据或状态，只用于诊断。

| 对照 | 主要问题 | 解释边界 |
| --- | --- | --- |
| 无历史 vs. 有历史 | 任务是否确实依赖历史 | 无历史模型可能利用常识猜中，需要逐例分析 |
| 可行范围内的全历史 vs. 压缩记忆 | 压缩是否带来损失或收益 | 全历史需使用同一读取模型，并核算读取成本 |
| 原始历史中的 oracle 证据 vs. 实际存储 | 必要证据是否已经被删除 | oracle 不代表可部署选择器 |
| 实际存储上的 oracle 检索 vs. 实际检索 | 问题是否出在检索 | 不能找回实际存储中不存在的内容 |
| 正确证据 vs. 正确结构化状态 | 问题是否出在阅读与整合 | 结构化状态本身提供了额外处理，属于诊断上界 |
| 正确状态下的行动 vs. 实际行动 | 问题是否出在应用记忆和执行 | 工具及环境故障需要单列 |

固定预算至少包括三个口径：总持久存储、每次读取上下文、累计写入与查询计算。若原始档案允许在外部长期保存，应明确列为外部档案，并计入容量或访问成本；不能一边声称已遗忘，一边免费回读它。

稳健性还应沿时间轴观察：历史增大后的收益是否维持，出现冲突后多久修正，错误是否传播，新增经历是否使旧任务退化。除平均质量外，报告关键约束的最差类别、失败率和匹配的置信区间。对于反复试验共享同一记忆库的实验，训练和测试经历的先后顺序也属于协议的一部分。

**最优先的下一步是定位主导误差。** 若性能差距主要来自证据已经丢失，应研究写入；若证据仍在而检索不到，应研究寻址；若证据已正确提供但行动仍不遵守，应研究记忆与策略的接口。这样得到的课题比预先决定要做一个更复杂的记忆架构更容易被证据支持。

## 10. 证据边界与结论强度

对“整体闭环仍不可靠”的判断，证据来自问答、工具参数与持续任务等不同层次，可信度较高。对“具体哪个子问题在真实部署中占最大比例”，公开资料不足：缺少跨产品、跨任务、同一故障分类下的长期事故统计。因此，本报告给出的是机制层面的优先级，而不是市场故障率排名。

对未知未来查询下的写入价值、证据互补性和跨层撤回的建议，属于从机制与现有缺口出发的研究推论，仍需实验确认。文本上的成功不自动迁移到视觉，受控多会话任务也不等价于数月真实部署。

综合来看，Agent 记忆研究最有价值的进展，应当表现为：**同等预算下，经历越多，后续决策越可靠；当世界变化或旧认识出错时，系统还能及时修正。** 写入质量、召回率、摘要压缩率和图结构复杂度都可以帮助实现这一目标，但都需要通过后续任务来验证其价值。

## 11. 历史补充与选题边界

同日追溯早期工作后，需要进一步收窄前述方向一的新颖性边界。2018 年的 LEMN 已学习有限外部记忆中的保留策略，考虑记忆项的相对与历史重要性。[^24] ACL 2019 的 EMR 则明确研究在问题尚未给出时读取流式文本或视频、记忆满后学习替换，并在 TVQA 上验证。因此，“未知未来问题 + 有限记忆 + 学习保留”以及考虑条目间相对重要性的总体设定，都已有直接先例。[^25]

2025 年的 KVzip 通过上下文重建估计 KV 重要性，支持压缩结果被不同查询复用；StreamMem 进一步针对流式视频，用通用查询 token 的注意力维护固定大小的 KV 记忆。[^26][^27] 它们是已取得任务内效果的具体方法，不能把该领域描述为缺少解决方案。另一方面，重建或通用查询提供的是价值代理，其对罕见细节、分布外任务和长时间状态更新的有效性仍需单独验证。

LLM Agent 层面，Mem-α 用后续问答反馈训练记忆构建，报告从最多 30k token 的训练实例泛化到超过 400k token 的测试历史。[^28] 长度泛化提供了积极证据，但并不自动证明任意新任务泛化。后续课题应与这些先例比较，明确额外解决的是证据互补性、变化后的修正、分布变化，还是可核算总预算下的持续收益；上述方向仍是待验证建议，不是已确认的创新点。
