## 1. 分类原则与完整覆盖

### 1.1 三条路线按保存对象与读取接口区分

- **T1 压缩 token：**历史被保留为较短的潜 token／特征序列，之后经拼接、交叉注意力、编码或重建读取。使用者可以是生成模型、检索编码器或策略模型。
- **T2 KV 缓存：**历史以模型各注意力层已经计算好的 K/V 保存，后续查询在相应层直接使用。选择、合并、量化、外部检索与位置管理是细分技术。
- **T3 递归状态：**历史累积到隐状态、关联矩阵、SSM 状态或动态槽位／多状态集合中，由状态转移更新、状态读出参与当前计算。关联矩阵是其中一支，不再与递归状态同义。
- **O 其他：**以条件查表或参数模块为主要记忆机制的工作。它是当前三条路线之外的收纳项，不假定这些工作具有同一种技术。

**边界按运算角色判断。**token 也可以递归更新，KV 也可以经 EMA 聚合，因此出现“递归”“状态”“cache”不直接决定分类。普通推理产生临时 KV，也不足以将所有 Transformer 方法归入 T2。只用 embedding 检索原文、最终仍把原文放回上下文的普通 RAG，不能仅因使用向量就归为压缩 token；需要有相应的潜内容读取接口。

### 1.3 不参与一级分类的维度

- **任务：**文本问答、视频流、GUI、多 agent、机器人、视频生成只作为应用标签。
- **访问与组织：**检索、分层、双来源、图索引、熵触发、门控与模型路由可以跨路线组合。

## 2. T1：压缩 token

### 2.1 总体设计与细分技术

写入器把一段文本、视频或观察—动作历史 $H_t$ 压成 $m$ 个潜 token。它可以是选择／池化／合并、可学习查询、独立编码器或潜 token 生成器。若同时读取旧记忆，则形成递归 token 更新；若先检索历史再压缩，则形成检索后的潜输入。

$$
Z_t=C_\phi(H_t,Z_{t-1})\in\mathbb R^{m\times d},\qquad
\hat y_t=D_\theta\bigl([P_\psi(Z_t);E(q_t)]\bigr).
$$

这是统一接口示意：独立分块编码可去掉 $Z_{t-1}$；需要重建时，先由 $R(Z_t)$ 恢复文本，再回答。接口之外还可能存在原始轨迹库、图索引或近期工作窗口。

- **压缩内容：**先决定写入时是否知道未来问题，再选择定向压缩还是问题无关保留。未知问题场景需要兼顾短暂事件和精确事实，不能只保存主题概要。
- **查询压缩的具体设计：**例如 Q-Former 用少量可学习查询交叉读取长特征，查询之间交换信息，再投影到读取者的维度。查询向量是训练得到的参数，默认不是本次用户问题；它解决的是固定潜序列瓶颈。[Mem-W](https://arxiv.org/html/2605.09317v1#S3.SS2)
- **训练接口：**规则合并可以免训练；新压缩器通常需学习投影与读写对齐，读取者可冻结或适配。冻结读取者权重不等于省去把损失传回潜 token 的反向计算。Mem-W 正文与附录训练范围存在表述差别，附录包含 LoRA 与压缩模块，不能概括成所有适配参数都冻结。[Mem-W 附录 B.2](https://arxiv.org/html/2605.09317v1#A2.SS2)
- **容量边界：**每块固定 $m$ 个 token，不等于总记忆固定；持续新增块时，潜库仍会增长。检索键、实际内容向量与原始证据需分别计入存储。

下列细分按比较重点组织，每篇只在一个位置完整介绍；机制可以交叉，例如查询压缩也可用于图组织的历史库。

### 2.2 token 的选择、合并与预算控制

这些工作主要回答“留下哪些视觉表征、合并到多粗”。不同时间尺度和双 bank 都是 token 管理方式，不按视频时长或任务另分类。

- **团队与任务：**[厦门大学多媒体可信感知与高效计算教育部重点实验室（纪荣嵘、周易毅）](https://arxiv.org/html/2606.25658)；视频流。

### 2.3 查询压缩、编码器对齐与潜 token 生成

这些工作主要回答“怎样产生模型能读懂的短潜序列”。Q-Former、分块编码、重建与潜 token 生成是不同实现；写入器可以利用已有 KV，但分类取决于供后续读取的对象。

<a id="paper-L01"></a>

#### L01｜[LCLM](https://arxiv.org/abs/2606.09659)

- **时间与来源：**2026-06-08；后批补充 L。**技术：**T1。
- **团队与任务：**[NYU、Princeton、UMD、Columbia、Harvard、Meta FAIR、LLNL；Izmailov / Goldblum / Goldstein / Zhuang Liu 等团队](https://arxiv.org/html/2606.09659v1)；长文本／agent。

- **归类依据与比较重点：**读写接口联合对齐；和视频池化相比，重点从删减冗余扩展到“压缩后怎样被读懂”。

### 2.5 检索后的 token 组织与容量分配

这些工作主要改变检索来源、token 容量或输入组织。GUI、机器人、多 agent 和文本问答在这里作为任务标签，便于比较同一接口在不同使用者中的作用。

## 3. T2：KV 缓存

### 3.1 总体设计与细分技术

KV 记忆保留历史经过各层计算后的键和值，后续问题或生成步骤直接对其做注意力，复用已经完成的历史编码。

$$
o_\ell=\operatorname{softmax}\!\left(\frac{q_\ell K_\ell^{\top}}{\sqrt{d_k}}\right)V_\ell.
$$

- **选择与预算：**按 token、头、层、模态或片段选择 K/V；近期窗口、sink、重要性评分与跨层平滑可以组合。
- **摘要与聚合：**将部分历史汇聚到摘要 KV，或按 EMA 等规则更新记忆键值。合并一般不能等价复原原来的 softmax 输出，需验证不同问题下的信息损失。
- **外部检索：**历史库保存较多块，本次只加载相关 KV；需同时计算 CPU／磁盘空间、检索与主机到 GPU 的搬运成本。
- **位置与兼容性：**K/V 依赖模型、先前上下文、掩码与位置编码。完整前缀复用和任意历史块检索是不同协议；仅改变位置编号不能普遍恢复不同上下文之间的等价性。
- **训练要求：**规则淘汰、量化或固定检索可免训练；学习评分器、摘要器或检索器则需任务监督／蒸馏。缓存能保存重载，不意味着必须额外训练一个解码器。

HERMES 是分层缓存维护的具体例子：分深度估计重要性、跨层平滑、保留高分 K/V 并聚合淘汰摘要，另以 lazy／eager re-indexing 管理位置。它与按问题从外部库检索的 ReKV，在读取时机和存储协议上不同。[HERMES §3](https://arxiv.org/pdf/2601.14724)、[ReKV §3](https://arxiv.org/html/2503.00540v1#S3)

### 3.2 KV 选择、窗口与分层预算

这些工作对已形成的 K/V 决定保留范围和容量。窗口、模态敏感性、通用查询评分与跨层平滑，都是缓存管理策略。

- **视频理解与生成共享位置问题。**[HERMES](https://arxiv.org/abs/2601.14724)、[MemRoPE](https://arxiv.org/abs/2603.12513) 分别从长视频理解与生成出发处理缓存位置和聚合，任务虽不同，都落在层内缓存接口。
- **外部保存与状态补偿解决不同容量问题。**[ReKV](https://arxiv.org/abs/2503.00540)、[FlexMem](https://arxiv.org/abs/2603.29252) 保留可检索的较大历史库；[IndexMem](https://arxiv.org/abs/2605.25475)、[RetentiveKV](https://arxiv.org/abs/2605.04075) 将部分淘汰内容写入紧凑状态。前者增加总存储，后者承担近似恢复和关联干扰。

**特点与局限。**KV 可以直接复用历史计算，部分策略无需训练；代价是逐层存储、较强的模型与上下文绑定，以及淘汰和搬运开销。缓存压缩若发生在完整预填充之后，不能据压缩后大小推断写入峰值显存。

## 4. T3：递归状态

### 4.1 总体设计与细分技术

本类将旧历史累积为运行时状态，而不是继续保留逐片段 token 或逐 token 的 K/V 列表。统一写入与读取接口可以表示为：

$$
s_t=F_\phi(s_{t-1},x_t),\qquad r_t=R_\psi(s_t,q_t).
$$

具体模型也可先读取旧状态再写入；公式只是接口抽象，不规定所有工作的计算次序。

- **门控向量状态：**用保留／写入门控制历史的覆盖与累积，是理解 RNN／GRU／LSTM 状态的基础背景。本次选集中没有以这一基础结构为主的新独立条目，不额外凑文献。
- **关联矩阵：**保存键到值的动态映射，以矩阵乘查询读出；外积累积、delta 误差修正、归一化与多状态组织是细分设计。
- **SSM 状态：**通过结构化状态转移控制不同时间尺度的信息保留。具体转移可依赖输入，不应统一简化成常数衰减；RetentiveKV 在混合缓存中使用这一类状态。
- **读取接入：**状态读出可以调节注意力查询、补充注意力输出或参与残差计算，通常不返回可独立定位的历史条目。

以标量门控的 delta 更新为机制例子，令 $S_t\in\mathbb R^{d_v\times d_k}$，键与查询是 $d_k$ 维列向量，值是 $d_v$ 维列向量：

$$
S_t=\lambda_tS_{t-1}+\eta_t\bigl(v_t-S_{t-1}k_t\bigr)k_t^{\top},
\qquad r_t=S_tq_t.
$$

该式对应“旧状态预测误差＋保留门”的简化顺序；有的实现先衰减再计算误差，不能混写为同一个精确算法。δ-mem 使用逐维门控，并按“读旧状态—修正注意力—写当前信息”的顺序运行。[δ-mem §2–3](https://arxiv.org/html/2605.12357v1)

**与 T1 的边界。**VideoLLaMB 等也使用递归，但传递的主要对象是供模型读取的 token 序列，因此在 T1；关联矩阵与 SSM／动态槽位则用状态转移累积历史。数学上二者都能写成递归式，分类还必须看保存对象和读出算子。

### 4.2 关联矩阵与可学习读写

以下两篇以动态关联状态为主要记忆通路。比较重点是如何写入、如何读出以及读出如何改变主干计算。

<a id="paper-L12"></a>

#### L12｜[Metis](https://arxiv.org/abs/2607.26760)

- **时间与来源：**2026-07-29；后批补充 L。**技术：**T3。
- **团队与任务：**[MemTensor、人大（Xu Chen）、NUS（Tat-Seng Chua、Yang Zhang）、上海交大、同济等](https://arxiv.org/html/2607.26760v2)；跨交互语言任务。
- **方法简介：**local memory 保存动态矩阵及归一化向量，hyper memory 选择隐藏表示并执行写入；矩阵读出参与模型计算。
- **归类依据与比较重点：**历史累积到动态矩阵及归一化状态，并由学习的读写程序使用，主接口属于递归状态。

<a id="paper-L13"></a>

#### L13｜[δ-mem](https://arxiv.org/abs/2605.12357)

- **时间与来源：**2026-05-12；后批补充 L。**技术：**T3。
- **团队与任务：**[NTU / DeCLaRe Lab（Soujanya Poria）、Mind Lab、复旦、上海交大等](https://arxiv.org/html/2605.12357v1)；文本记忆／推理。
- **方法简介：**从旧状态读出关联向量，修正注意力查询与输出，再按门控 delta rule 将当前键值误差写回矩阵。
- **归类依据与比较重点：**历史写入实例状态，状态读出修正注意力；冻结主干与状态在线更新是不同层面的操作。

### 4.3 擦除与写入规则：从控制强度到控制地址

两项新增工作都改进 delta 记忆编辑：Gated DeltaNet-2 拆开擦除与写入的通道门，EDA 再让擦除与写入使用不同地址。这里比较的是状态更新算子，并非缓存删掉多少条目。

<a id="paper-R01"></a>

#### R01｜[Gated DeltaNet-2](https://arxiv.org/abs/2605.22791)

- **时间与来源：**2026-05-21；本轮状态补充 R。**技术：**T3。
- **团队与任务：**[NVIDIA Research（Ali Hatamizadeh、Yejin Choi、Jan Kautz）](https://arxiv.org/html/2605.22791v1)；语言建模、常识推理、长上下文检索。
- **方法简介：**在通道衰减之外，将旧关联的擦除门与新值的写入门拆开；矩阵状态仍递归更新，并提供分块并行算法。
- **归类依据与比较重点：**修改固定大小关联状态的更新算子，属于 T3；重点是擦除与写入的控制粒度，而非 token 或 KV 条目筛选。
- **训练与证据范围：**论文报告 1.3B 模型、100B FineWeb-Edu token 预训练，并做语言与 RULER 检索评测；这是主干训练级配置。
- **单轮与长期边界：**主要验证序列内状态记忆和长上下文检索，不据此宣称跨会话恢复。

<a id="paper-R02"></a>

#### R02｜[Erase-then-Delta Attention（EDA）](https://arxiv.org/abs/2606.26560)

- **时间与来源：**2026-06-25；本轮状态补充 R。**技术：**T3。
- **团队与任务：**[阿里巴巴 Qwen Team、南京大学、浙江大学](https://arxiv.org/html/2606.26560v1)；语言预训练与长上下文理解。
- **方法简介：**先沿单独学习的擦除地址清除旧信息，再沿当前写入地址执行 delta 纠错写入，使清理位置与新增内容的位置可以不同。
- **归类依据与比较重点：**核心是递归关联状态的有序更新；和 Gated DeltaNet-2 的门控拆分相比，进一步改变擦除与写入地址的耦合。
- **训练与证据范围：**评测覆盖 dense 2.5B 与 MoE 25B-A2.8B 预训练；MoE 另做 80B token 长上下文中期训练及 4K–128K 评测。
- **单轮与长期边界：**主要验证上下文内记忆管理；尚不能由状态编辑能力直接推断跨会话事实管理。

### 4.4 状态容量组织：稀疏槽位与动态多状态

单一密集状态之外，可以增加可寻址槽位，或维护多个按时间组织的压缩状态。前者限制每步访问范围，后者决定何时分段、何时合并；两者都需要核算总状态容量与不可逆的信息损失。

<a id="paper-R03"></a>

#### R03｜[Sparse Delta Memory（SDM）](https://arxiv.org/abs/2607.07386)

- **时间与来源：**2026-07-08；本轮状态补充 R。**技术：**T3。
- **团队与任务：**[Meta FAIR、Inria／ENS-PSL、图宾根大学](https://arxiv.org/html/2607.07386v1)；语言建模、上下文学习与长上下文检索。
- **方法简介：**将密集小矩阵扩展为较大的动态槽位状态；通过 product-key 寻址选择少量槽位读取和执行 gated-delta 写入，未选中槽位保留。
- **归类依据与比较重点：**槽位内容随当前历史在线改写，因此主归 T3。它虽然采用查表式寻址，但不同于 Engram 的静态条件表。
- **训练与证据范围：**在匹配参数与 FLOPs 的设置下比较状态容量和检索能力；原文默认学习初始状态，并单独消融，本文只聚焦在线递归部分。
- **单轮与长期边界：**较大状态不等于零存储成本；局部注意力缓存和可学习初始状态需另计，未宣称完成跨会话恢复验证。

<a id="paper-R04"></a>

#### R04｜[Dynamic Linear Attention（DLA）](https://arxiv.org/abs/2606.10650)

- **时间与来源：**2026-06-09；本轮状态补充 R。**技术：**T3。
- **团队与任务：**[Ohio State University、University of Michigan、ByteDance Seed](https://arxiv.org/html/2606.10650v1)；常识推理、上下文检索与长序列建模。
- **方法简介：**按信息变化动态确定状态边界，在语义变化处保留较细状态；达到容量上限时，合并相邻低信息状态，维持有时间顺序的状态集合。
- **归类依据与比较重点：**cache 中保存的是多个压缩递归状态，不是逐 token K/V，归 T3；预算管理可以发生在状态层面。
- **训练与证据范围：**论文在 Mamba-2-780M 与 Gated DeltaNet-1.3B 两种骨干上预训练，并在 16 个数据集评测。
- **单轮与长期边界：**研究序列内多状态保留；容量上限下的合并仍会丢失信息，不能等同于保留全部历史。

### 4.5 递归状态与显式注意力混合

本节将 IndexMem、RetentiveKV 正式计入递归状态，与新增的 Qwen3.5 一起比较。前两者将淘汰内容转移到状态，后者在模型层级组合递归计算与全注意力；混合位置不同，但都需要同时核算状态和 KV。

<a id="paper-L14"></a>

#### L14｜[IndexMem](https://arxiv.org/abs/2605.25475)

- **时间与来源：**2026-05-25；后批补充 L。**技术：**T2＋T3。
- **团队与任务：**[HKUST（Yike Guo、Sirui Han）、浙大；微软研究院有官方论文条目](https://arxiv.org/html/2605.25475v2)；长文本推理。
- **方法简介：**indexer 留下部分 KV；被淘汰的键值进入紧凑关联状态，状态读出对普通注意力作残差补偿。
- **归类依据与比较重点：**T3＋T2：递归状态补偿被淘汰 KV；按用户确认的混合方法口径主列递归状态，KV 路线保留交叉引用。

<a id="paper-L15"></a>

#### L15｜[RetentiveKV](https://arxiv.org/abs/2605.04075)

- **时间与来源：**2026-04-14；后批补充 L。**技术：**T2＋T3。
- **团队与任务：**[浙江大学、阿里巴巴](https://arxiv.org/html/2605.04075v1)；多模态推理。
- **方法简介：**显式保留部分 KV，将待淘汰内容通过熵相关状态转移写入 SSM 式关联状态，供后续读取。
- **归类依据与比较重点：**T3＋T2：递归状态补偿被淘汰 KV；按用户确认的混合方法口径主列递归状态，KV 路线保留交叉引用。

<a id="paper-R06"></a>

#### R06｜[Qwen3.5](https://qwen.ai/blog?id=qwen3.5)

- **时间与来源：**2026-02（官方模型发布）；本轮状态补充 R。**技术：**T3＋T2。
- **团队与任务：**[阿里巴巴 Qwen Team](https://huggingface.co/Qwen/Qwen3.5-397B-A17B)；文本推理、图像／视频理解与 agent。
- **方法简介：**原生视觉语言骨干组合 Gated DeltaNet 递归层与全注意力层；前者用状态累积历史，后者保留注意力读取能力。
- **归类依据与比较重点：**T3＋T2 混合架构，按本版约定主列递归状态；原生多模态说明状态路线已进入大规模 VLM，不代表已验证跨会话记忆。
- **训练与证据范围：**属于基础模型预训练与后训练成果。这里只引用官方架构和模型卡，不将整个模型训练资源估算成小模块适配预算。
- **单轮与长期边界：**递归层的状态固定不代表整模缓存固定：全注意力层仍有 KV；需要同时保存两者才能讨论完整恢复。
- **文献类型：**官方模型技术发布与模型卡，计为 1 项工作，不写成独立预印本论文。

### 4.6 跨层读写协同与比较研究

除了改变单层更新，还可以研究递归记忆的内部信号怎样跨层传递。比较研究有助于区分更新规则、优化器和混合结构各自造成的收益。

<a id="paper-R05"></a>

#### R05｜[Linear Attention Architectures／CLVR](https://arxiv.org/abs/2607.07953)

- **时间与来源：**2026-07-08；本轮状态补充 R。**技术：**T3。
- **团队与任务：**[ETH Zurich D-INFK、ETH AI Center（Imanol Schlag 团队）](https://arxiv.org/html/2607.07953v1)；语言建模与递归架构比较。
- **方法简介：**统一比较 Delta 系列状态更新，并研究跨层传递写入误差或写入值。CLVR 将写入值送入对齐的隐状态流，加强层间信息共享。
- **归类依据与比较重点：**被路由的信号来自递归记忆写入，保留原有状态更新骨架，归 T3 的读写协同设计；同时也是比较研究。
- **训练与证据范围：**主比较为 350M 参数、15B token；直接转发写入误差未改善基线，CLVR 在匹配实验中有小幅收益。速度数据是训练吞吐。
- **单轮与长期边界：**没有实测推理速度或跨会话持久记忆结论，不能将训练吞吐当作长期读取效率。

### 4.7 原有工作与补充工作合并后的脉络

- **写得更准确：**[δ-mem](https://arxiv.org/abs/2605.12357)、[Metis](https://arxiv.org/abs/2607.26760) 关注读写接口；[Gated DeltaNet-2](https://arxiv.org/abs/2605.22791)、[Erase-then-Delta Attention（EDA）](https://arxiv.org/abs/2606.26560) 分别扩展擦写门与擦写地址的控制。
- **保存更多且减少干扰：**[Sparse Delta Memory（SDM）](https://arxiv.org/abs/2607.07386)、[Dynamic Linear Attention（DLA）](https://arxiv.org/abs/2606.10650) 从稀疏访问和多状态合并扩展容量组织，不再将递归记忆限定为一个小矩阵。
- **与主干协同：**[IndexMem](https://arxiv.org/abs/2605.25475)、[RetentiveKV](https://arxiv.org/abs/2605.04075)、[Qwen3.5](https://qwen.ai/blog?id=qwen3.5) 在缓存管理或模型层级组合显式注意力；[Linear Attention Architectures／CLVR](https://arxiv.org/abs/2607.07953) 研究层间写入信号复用。

**特点与局限。**状态不必随历史逐 token 扩展，但有限状态、合并和稀疏路由仍可能遗忘或干扰。新增工作的核心证据主要来自序列内检索、语言建模或多模态基础能力；长序列成绩不能直接视为跨会话持久记忆验证。

**训练要求随改造位置变化。**外挂读写模块可冻结主干；修改递归骨干通常需要预训练或继续训练；稀疏状态还需相应读写内核。论文公开的大模型预训练配置不能被换算成统一的“单卡记忆模块”门槛。

## 5. 其他：不以三种接口为主要机制的工作

本节保留原有 3 篇以保证原有 40 篇完整覆盖。它们不再与压缩 token、KV 缓存、递归状态并列为两个独立研究路线，也不混入当前六页稿的三条路线。

### 5.1 离散地址的条件向量表

两篇工作按离散局部模式读取向量表。表项可以在预训练中学习，也可以从冻结模型离线构建；其主要作用是条件知识查找。

<a id="paper-L19"></a>

#### L19｜[Memory Grafting](https://arxiv.org/abs/2605.20948)

- **时间与来源：**2026-05-20；后批补充 L。**技术：**O。
- **团队与任务：**[清华大学（Chun Yuan）、微软亚洲研究院（Yeyun Gong、Yan Lu）](https://arxiv.org/html/2605.20948v1)；语言预训练。
- **方法简介：**冻结模型离线产生 n-gram 隐藏向量；按最长匹配后缀读取向量表，投影与门控后融合入骨干。
- **归类依据与比较重点：**主要记忆是离散 n-gram 地址对应的条件向量表，不是本次历史压出的 token 序列或递归状态。

<a id="paper-L20"></a>

#### L20｜[Engram](https://arxiv.org/abs/2601.07372)

- **时间与来源：**2026-01-12；后批补充 L。**技术：**O。
- **团队与任务：**[DeepSeek-AI、北京大学（Huishuai Zhang、Dongyan Zhao）](https://arxiv.org/html/2601.07372v2)；语言预训练。
- **方法简介：**规范化局部 token 模式，经多头哈希读取可学习 embedding 表，再用当前隐藏状态门控融合。
- **归类依据与比较重点：**推理时按离散模式查表并门控融合；表值可训练，不意味着它属于递归状态或 KV 缓存。

### 5.2 上下文蒸馏为参数模块

这篇工作将历史上下文的影响写入可调用参数模块，保留在“其他”用于边界比较，不作为当前三条路线的扩展分支。

<a id="paper-L18"></a>

#### L18｜[Context Distillation as Latent Memory Management](https://arxiv.org/abs/2605.28889)

- **时间与来源：**2026-05-27；后批补充 L。**技术：**O。
- **团队与任务：**[CUHK（Qiang Xu）、华为诺亚方舟实验室](https://arxiv.org/html/2605.28889v1)；上下文问答。
- **方法简介：**每个上下文蒸馏出独立 LoRA；查询时检索并路由模块，以共享前缀 KV 和首 token 熵控制启用。
- **归类依据与比较重点：**上下文信息经优化写入独立 LoRA，读取时改变模型参数映射；共享前缀 KV 是配套加速。

### 5.3 为什么放在“其他”

- **条件查表：**[Engram](https://arxiv.org/abs/2601.07372)、[Memory Grafting](https://arxiv.org/abs/2605.20948) 主要区别在表值来自训练还是离线模型构建。读取都是离散地址查表与门控融合，不能因为输出一个向量就称为本次历史的 token 压缩。
- **参数模块：**[Context Distillation as Latent Memory Management](https://arxiv.org/abs/2605.28889) 将上下文影响蒸馏到 LoRA。它虽使用模块检索和前缀 KV，但核心存储是可调用参数增量，因此不因辅助缓存而主列 T2。
- **本节不是统一方法家族。**查表容量、哈希冲突与参数写入成本是不同问题；当前讨论仅说明与三条路线的接口边界。

## 6. 三批材料合并后的方法脉络

以下按设计问题梳理联系，不声称论文之间存在已被作者确认的直接继承关系。

### 6.1 压缩 token：减少冗余 → 对齐读写 → 条件分配与复用

早期视频方法 [MovieChat](https://arxiv.org/abs/2307.16449)、[MA-LMM](https://arxiv.org/abs/2404.05726)、[VideoLLaMB](https://arxiv.org/abs/2409.01071) 提供合并、bank 与递归 bridge 的对照。2026 年的 [CausalMem](https://arxiv.org/abs/2606.25658)、[FluxMem](https://arxiv.org/abs/2603.02096)、[R3-Streaming](https://arxiv.org/abs/2605.17921) 继续细化预算与冗余处理；[LCLM](https://arxiv.org/abs/2606.09659)、[NextMem](https://arxiv.org/abs/2603.15634)、[Mem-W](https://arxiv.org/abs/2605.09317) 强化编码和读取接口；[ElasticMem](https://arxiv.org/abs/2605.30690)、[HyMEM](https://arxiv.org/abs/2603.10291)、[LatentStream](https://arxiv.org/abs/2609.04131) 将问题条件、结构检索或持续演化加入同一路线。需要比较的变量是容量、压缩感受范围、读取者以及训练目标。

### 6.2 KV 缓存：保留或总结 → 分层管理与检索 → 状态补偿

[Video-XL](https://arxiv.org/abs/2409.14485)、[ReKV](https://arxiv.org/abs/2503.00540)、[StreamMem](https://arxiv.org/abs/2508.15717) 分别展示总结 KV、外部历史检索和问题无关保留。[HERMES](https://arxiv.org/abs/2601.14724)、[MuKV](https://arxiv.org/abs/2605.22269)、[OmniMem](https://arxiv.org/abs/2606.07577)、[WeaveTime](https://arxiv.org/abs/2602.22142)、[MemRoPE](https://arxiv.org/abs/2603.12513)、[LycheeMemory](https://arxiv.org/abs/2602.08382) 在评分、粒度、模态、位置及块读取上继续细化；[IndexMem](https://arxiv.org/abs/2605.25475)、[RetentiveKV](https://arxiv.org/abs/2605.04075) 增加状态通路。外部库与有限状态不是等价压缩：前者保留更多条目，后者改变被淘汰信息的表示。

### 6.3 递归状态：读写纠错 → 稀疏与多状态扩容 → 跨层与混合主干

[δ-mem](https://arxiv.org/abs/2605.12357)、[Metis](https://arxiv.org/abs/2607.26760) 提供状态读写与注意力调节的接口；[Gated DeltaNet-2](https://arxiv.org/abs/2605.22791)、[Erase-then-Delta Attention（EDA）](https://arxiv.org/abs/2606.26560) 细化擦除和写入控制；[Sparse Delta Memory（SDM）](https://arxiv.org/abs/2607.07386)、[Dynamic Linear Attention（DLA）](https://arxiv.org/abs/2606.10650) 扩展可用容量并减少无差别覆盖；[Linear Attention Architectures／CLVR](https://arxiv.org/abs/2607.07953)、[Qwen3.5](https://qwen.ai/blog?id=qwen3.5)、[IndexMem](https://arxiv.org/abs/2605.25475)、[RetentiveKV](https://arxiv.org/abs/2605.04075) 将状态与层间计算或显式注意力结合。它们覆盖不同设计层级，可分别比较更新规则、容量组织、接口与整模架构，不按任务硬分技术类别。

### 6.4 团队脉络作为辅助视角

颜水成参与的 [L²-VMAS](https://arxiv.org/abs/2602.00471)、[Mem-W](https://arxiv.org/abs/2605.09317)、[LaMem-VLA](https://arxiv.org/abs/2607.07608)、[StreamFlow](https://arxiv.org/abs/2608.10949) 以及蚂蚁／NUS 合作的 [LatentStream](https://arxiv.org/abs/2609.04131)，可在同一 token 语言下比较：来源分工、共享压缩、策略输入和流式演化分别改变不同技术环节。NUS 的 Chua／Yang Zhang 合作线涉及 [NextMem](https://arxiv.org/abs/2603.15634)、[Metis](https://arxiv.org/abs/2607.26760)，Wee Sun Lee 团队的 [One Token per Multimodal Evidence](https://arxiv.org/abs/2606.10572) 则关注证据压缩；不能把 NUS 的所有工作视为同一团队或同一方法。

## 7. 应用标签与单轮／长期使用边界

### 7.1 任务如何映射到技术，而不成为一级分类

- **文本事实问答、长上下文推理与个性化：**输入文档或交互历史与问题，输出答案，需要保留实体、数值和跨段条件。[LCLM](https://arxiv.org/abs/2606.09659)、[NextMem](https://arxiv.org/abs/2603.15634)、[ElasticMem](https://arxiv.org/abs/2605.30690) 使用 token，[LycheeMemory](https://arxiv.org/abs/2602.08382)、[IndexMem](https://arxiv.org/abs/2605.25475) 使用 KV 或混合状态，[δ-mem](https://arxiv.org/abs/2605.12357)、[Metis](https://arxiv.org/abs/2607.26760) 使用递归状态；它们可在相同历史依赖任务下比较。
- **连续视频、长视频与音视频问答：**输入画面流及后续问题，输出事件答案，需要跨片段身份、顺序与稀有细节。[LatentStream](https://arxiv.org/abs/2609.04131)、[StreamFlow](https://arxiv.org/abs/2608.10949)、[FluxMem](https://arxiv.org/abs/2603.02096) 与 [OmniMem](https://arxiv.org/abs/2606.07577)、[MuKV](https://arxiv.org/abs/2605.22269)、[HERMES](https://arxiv.org/abs/2601.14724)、[ReKV](https://arxiv.org/abs/2503.00540) 分别提供 token 和 KV 接口。音频支持、问题到达时机与回看权限应单独记录。
- **GUI、多 agent 与机器人决策：**输入当前观察、指令和历史，输出操作或动作，需要保存进度、过去选择和不可见状态。[Mem-W](https://arxiv.org/abs/2605.09317)、[HyMEM](https://arxiv.org/abs/2603.10291)、[L²-VMAS](https://arxiv.org/abs/2602.00471)、[LatentMem](https://arxiv.org/abs/2602.03036)、[LaMem-VLA](https://arxiv.org/abs/2607.07608) 的使用者不同，但都包含潜 token 内容通路。[ElasticMem](https://arxiv.org/abs/2605.30690) 的 ALFWorld 结果也不应直接等同于真实机器人视觉控制。
- **视频生成与语言预训练：**[MemRoPE](https://arxiv.org/abs/2603.12513) 用 KV 支持长视频生成；[Memory Grafting](https://arxiv.org/abs/2605.20948)、[Engram](https://arxiv.org/abs/2601.07372) 研究预训练中的条件查表。任务标签可以相邻讨论，技术归属仍分别为 T2 与其他。

- **递归语言模型与多模态混合主干：**[Gated DeltaNet-2](https://arxiv.org/abs/2605.22791)、[Erase-then-Delta Attention（EDA）](https://arxiv.org/abs/2606.26560)、[Sparse Delta Memory（SDM）](https://arxiv.org/abs/2607.07386)、[Dynamic Linear Attention（DLA）](https://arxiv.org/abs/2606.10650)、[Linear Attention Architectures／CLVR](https://arxiv.org/abs/2607.07953) 主要研究语言建模、检索或训练行为；[Qwen3.5](https://qwen.ai/blog?id=qwen3.5) 涉及文本、视觉理解与 agent。骨干能力与外部经历的保存／取回是不同评测层次。

上述输入输出是本报告的比较抽象，具体基准与协议以各论文为准。Qwen3.5 提供原生多模态混合主干的工业实例，但其他状态方法向持续视频和具身任务的迁移仍需逐项验证。

### 7.2 单轮、跨问题与跨会话分别意味着什么

- **单轮使用：**记忆只服务一次问答／推理请求，结束后丢弃或重建。单轮也可能包含长视频、长时间间隔证据和多次模型前向计算。
- **跨问题复用：**同一历史的记忆继续保留，供不同问题读取。每题重新编码原始历史，不算复用之前写好的记忆。
- **跨会话持久化：**保存到持久存储，在调用结束或进程重启后恢复或取回。需要记录内容、索引／寻址方式、模型版本及恢复协议。

**远期回忆与保存边界是两个维度。**单轮可以测“很久以前发生了什么”；跨问题可实现会话内长期记忆；跨会话则进一步处理保存和取回。输入很长、状态固定、缓存卸载到 CPU 或张量能够落盘，都不单独证明长期回忆质量。

### 7.3 三条路线如何支持长期使用

- **压缩 token：**可以保存潜序列块并建立索引，后续查询加载相关块，再由兼容读取者处理。[HyMEM](https://arxiv.org/abs/2603.10291) 的轨迹嵌入读取、[ElasticMem](https://arxiv.org/abs/2605.30690) 的离线 bank，与 [Mem-W](https://arxiv.org/abs/2605.09317)、[LaMem-VLA](https://arxiv.org/abs/2607.07608) 的检索后压缩应分开比较；“取回潜 token”和“取回原始历史再压缩”不是同一步骤。
- **KV 缓存：**共享历史可跨问题复用，也可保存到外部存储后检索加载。[ReKV](https://arxiv.org/abs/2503.00540) 明确使用 RAM／磁盘历史 KV；完整前缀恢复和选段读取都需要处理模型与位置兼容性，不能宣称任意 KV 拼接与原始完整上下文等价。
- **递归状态：**可以跨问题保留，并保存完整状态快照后恢复。关联矩阵、归一化量、必要的局部 KV 与位置计数应按架构一并处理；快照主要恢复计算状态，通常不能直接按事件逐条检索。持久保存也不能找回已经被覆盖的信息。

本节的保存流程是机制分析；没有将这些工作统一标为“已完成跨会话恢复实验”。保存与重载本身不必新增训练，长期保留质量则需长间隔、多次回访、更新与干扰评测。

## 8. 统一设计比较与后续可验证问题

### 8.1 对齐三个主要存储预算

设每数值占 $b$ 字节，token 数为 $m$、维度为 $d$，KV 层数为 $L$、头数为 $h_{kv}$、每层每头位置数为 $n$、头维度为 $d_h$，矩阵状态副本数为 $p$：

$$
M_{\mathrm{token}}=bmd,\qquad
M_{\mathrm{KV}}=2bLnh_{kv}d_h,\qquad
M_{\mathrm{state}}=bpd_vd_k.
$$

这里按单样本估算，状态式只适用于矩阵部分；不同层或模态预算不同时要逐项求和。总存储还包括索引、元数据、外部原始证据、归一化量、普通查询 KV 和共享模型权重。多个潜块、缓存块或状态快照的总量需要另外累加。

### 8.2 每条路线最需要控制的变量

- **压缩 token：**token 数与维度、压缩器可见历史、写入时是否知道问题、读取者是否共同训练；测精确事实恢复与读写接口迁移。
- **KV 缓存：**逐层预算、选择分数、摘要比例、位置处理和外部库大小；测细节保留、跨问题稳定性、预填充峰值和检索搬运延迟。
- **递归状态：**状态维度、副本数、读写次序、写入／遗忘门和重置边界；测关联冲突、矛盾更新、长间隔遗忘和禁用状态的消融。
- **其他：**条件表报告命中、冲突与查表带宽；参数模块报告单次写入训练成本、模块选择及错误调用影响，不硬套 token 或 KV 条目预算。

### 8.3 建议的共同评测协议

1. **单轮基线：**每题独立写入并回答，同时报告写入和读取成本；问题感知压缩与未知问题写入分开评测。
2. **跨问题与长间隔：**先写入同一历史，多题共享；插入干扰和新事实，测早期证据的保持及更新能力，避免每题重新提供完整原始历史。
3. **保存与恢复：**清空运行时记忆后，仅恢复所声明的持久内容；测恢复前后质量、检索召回、总存储和冷启动延迟。
4. **混合方法消融：**对 IndexMem／RetentiveKV 一类设计，先比较纯 KV、仅状态和二者组合，并控制总预算，再讨论更复杂的触发或分层。

这些是待验证建议。文献结果属于作者报告；本次工作是对原有 40 篇的联合分类、6 项新增状态工作的原文调研与接口核对，**未运行论文复现、模型训练或长期记忆评测**。
