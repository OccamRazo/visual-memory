## 1. 分类原则：按记忆的计算形态，任务另列

本报告只使用一个技术坐标：**持久记忆以什么对象保存，又通过什么算子参与模型计算。**由此划分为压缩 token、KV 缓存、关联矩阵、条件向量表和模型参数五类。文本、视频、GUI、多 agent、机器人只标记应用范围，不定义技术分支。

分类单位是**技术构件**，不是整个系统的唯一标签。一篇论文可以组合多类构件。例如 IndexMem 同时维护显式 KV 和淘汰信息的关联状态，应标记为 T2＋T3。常规 Transformer 运行时产生临时 KV，不足以让所有方法都被计入 T2；只有被方法明确维护、选择或复用为历史记忆的缓存才计入。

| 技术类别 | 实际保存的对象 | 主要读取算子／接入位置 | 识别要点 | 代表工作 |
|---|---|---|---|---|
| **T1 压缩 token 记忆** | 一组潜向量 $Z\in\mathbb R^{m\times d}$ | 将 $Z$ 作为输入序列，交给编码器／解码器或重建器 | 读取时仍要将记忆 token 编码或解码；不是直接恢复每层 K/V | Mem-W；LCLM、NextMem 为其他实现 |
| **T2 KV 缓存记忆** | 每层历史 $K^{\ell},V^{\ell}$ | 在对应注意力层直接计算 $\operatorname{Attn}(q,K,V)$ | 复用已编码历史，需处理层间一致性、位置及缓存搬运 | HERMES；StreamMem、ReKV 为不同管理策略 |
| **T3 关联矩阵记忆** | 固定维关联映射 $S\in\mathbb R^{d_v\times d_k}$ | 用 $Sq$ 读出，再以递归规则修改 $S$ | 历史被叠加或纠错写入状态，不保留逐 token K/V 列表 | δ-mem；Metis、RetentiveKV 为相关实现 |
| **T4 条件查表记忆** | 按离散地址组织的向量表 $E$ | $E[a(x)]$ 查表，再投影／门控融合 | 地址来自 token 模式等离散键；不是遍历实例库做语义近邻搜索 | Engram；Memory Grafting 改变构表来源 |
| **T5 参数记忆** | 可调用的模型参数增量 $\Delta\theta_i$ | 以 $f_{\theta+\Delta\theta_i}$ 改变模型前向映射 | 信息经优化写进参数模块，而非作为额外 token 或关联状态读出 | Context Distillation as Latent Memory Management |

这里的“五类”是对当前文献集合的技术分解，不声称是领域公认的唯一分类。边界由运算角色决定：Engram 的表可以用梯度训练，但运行时是离散查表，归 T4；关联矩阵也常被称为 fast weights，但若实例历史由递归规则写入、通过 $Sq$ 读取，归 T3。T5 则指调用经优化得到的参数模块来改变模型映射。

**以下维度与五类正交，应在每类内部比较：**

| 可组合设计 | 具体问题 | 为什么不单列成同级类别 |
|---|---|---|
| 递归／分块写入 | 每次编码是否依赖旧状态？ | token、KV 摘要、关联矩阵都可以递归更新 |
| 检索／全量读取 | 读取全部记忆，还是选一部分？ | 可检索 token、KV 块、参数模块，检索不决定载体 |
| 分层／多时间尺度 | 近期与远期信息分配多少容量？ | 可以在 token bank、KV 层或多组矩阵上实现 |
| 熵触发／学习门控 | 何时写、何时读、是否启用？ | 是访问策略；与存储对象无一一对应关系 |
| 自蒸馏／重建／RL | 用什么信号训练记忆接口？ | 是学习目标；同一目标可训练多种记忆载体 |
| 图组织／角色条件／模型路由 | 怎样组织来源、提供上下文和分配计算？ | 是索引或控制层，不应与 token、KV 等并列 |

## 2. T1：压缩 token 记忆

### 2.1 总体设计

这条路线将长历史变成较短的潜序列，再让模型像读取其他输入一样读取它。写入器可以是池化、聚类合并、可学习查询、前馈编码器或自回归生成器；“压缩 token”不要求所有实现都通过训练获得。

1. **确定写入单元。**将文本段、帧特征或观察—动作段表示为 $H_t$。写入时可以只看当前块，也可以同时输入旧记忆；这决定了它是分块编码还是递归编码。
2. **构造压缩瓶颈。**指定 $m$ 个潜 token，用可学习查询从长输入中抽取内容，或通过池化／合并得到潜表示。$m$、维度及数值精度共同决定容量，单说“一个 token”无法确定字节数。
3. **对齐读取接口。**将潜表示投影到使用者的嵌入空间。使用者可以是答案模型、检索编码器或事实重建器，不能一律假定为最终答案解码器。
4. **选择读取路径与训练目标。**直接读取适合节省生成上下文；先重建便于恢复原文；二者可分别用任务损失、重建损失和蒸馏损失训练。是否另保留原始证据库，需要单独声明。

以下是路线抽象，省略具体模型的掩码和位置处理：

$$
Z_t=C_\phi(H_t,Z_{t-1}),\qquad
U_t=[P_\psi(Z_t);E(q_t)],\qquad
\hat y_t=D_\theta(U_t).
$$

独立分块编码可去掉 $Z_{t-1}$；若先重建，则先执行 $\hat x=R(Z)$，再以 $\hat x$ 回答。每块固定 $m$ 个 token 仍可能形成随块数增长的库；只有进一步约束总块数，才是固定总容量。

### 2.2 代表工作：Mem-W 的共享潜 token 压缩器

**构造输入。**每段历史包含观察、结构化动作类型及参数。冻结编码器先生成上下文化特征；已完成的历史轨迹带成功／失败结果，正在执行的片段用“结果未知”标记，避免将未来结果提前写入。

**压缩与共享接口。**$K$ 个可学习查询经 Q-Former 对长特征执行交叉注意力，再投影成 $K\times d$ 潜 token。历史经验与本轮较早步骤使用同一个压缩器，因此两种来源都能进入同一嵌入空间。为突出核心算子，下式省略结果嵌入与段落边界：

$$
H=G_\theta(s),\qquad
Z=P_\phi\!\left(\operatorname{QFormer}_\phi(Q,H)\right),
\quad Q\in\mathbb R^{K\times h}.
$$

**读取。**检索器从经验库选择少量轨迹并压缩；本轮过期历史按段压缩；两类潜 token 与当前画面、指令、近期原始步骤组成输入。真正统一它们的是输入嵌入接口；经验库和本轮历史只是来源标签。

**训练。**冻结编码器和 agent，先让使用短潜记忆的 student 模仿看到长历史的 teacher，再用任务结果优化压缩器。离散 Top-M 检索并不因这个训练目标而自动可微。原文用双来源消融检查互补性；它没有证明潜 token 能无损重建所有经历。[Mem-W §3.2–3.4、§4.4](https://arxiv.org/html/2605.09317v1)。

### 2.3 同一路线的演进与差异

MovieChat 的 token 合并、MA-LMM 的视觉／查询 bank、VideoLLaMB 的递归 bridge，都是 token 载体的不同写入器。LCLM 将重点放在编码器—解码器的联合对齐；NextMem 强调潜序列到事实文本的可重建性；One Token 同时优化检索和生成；FlashMem 则复用已有 KV 来生成潜 token。**KV 是写入计算来源，不代表输出就属于 KV 记忆。**

颜水成相关合作中的 L²-VMAS、Mem-W、LaMem-VLA、StreamFlow、LatentStream 主要落在这一技术家族。它们的区别应放在写入条件、来源分工、触发规则和 token 注入位置，而不是另设“多 agent 记忆”或“具身记忆”类别。详细论文映射见 §7。

## 3. T2：KV 缓存记忆

### 3.1 总体设计

token 记忆保存的是待使用的潜序列，KV 路线则保存这些内容已经经过各层模型计算后的键值。它将重复编码成本换成更大的、与模型层和位置紧密绑定的存储。

1. **增量预填充。**新片段经骨干编码，逐层产生新的 K/V，与历史缓存一起形成候选集合。
2. **选择或压缩。**为每层或每块设预算，依据时间、注意力、频率、扰动敏感性等保留部分条目；也可将被淘汰部分合并成摘要 KV。
3. **维护一致性。**缓存必须知道所属层、原始位置、模态及可见范围。跨层独立淘汰和位置重排可能改变同一历史内容的表示，需要显式处理。
4. **读取。**查询直接对保留下来的 K/V 做注意力；若缓存放在 CPU／磁盘，还需先检索和搬回对应块。保留外部完整库与只保留压缩库，是两种资源协议。

$$
\mathcal I_\ell=\operatorname{TopB}(s_\ell),\qquad
K_\ell'=K_\ell[\mathcal I_\ell],\quad
V_\ell'=V_\ell[\mathcal I_\ell],\qquad
 o_\ell=\operatorname{softmax}\!\left(\frac{q_\ell K_\ell'^{\top}}{\sqrt{d_k}}\right)V_\ell'.
$$

这只表示“选择后读取”这一支；学习总结 KV、外部块检索和状态补偿分别需要额外操作，不能都写成 Top-B 淘汰。

### 3.2 代表工作：HERMES 的逐层评分与缓存维护

**层内评分。**HERMES 将不同深度的注意力行为作为设计依据：浅层偏重近期 token，深层偏重稳定的注意力锚点，中层混合两种分数。未来问题未知时使用通用提示估计注意力重要性，而非提前利用真实测试问题。

**层间平滑与压缩。**从深层向浅层传播重要性信号，缓解同一缓存位置在各层被独立淘汰造成的不一致。依据平滑分数为各层选择固定预算 K/V；被淘汰内容另聚合为层内摘要 token，并保留其缓存。

**位置与读取。**持续视频会使位置编号增长。HERMES 提供接近位置上限时才处理的 lazy re-indexing，以及每次压缩都处理的 eager re-indexing。问题到来后直接使用已经维护好的缓存，无需再启动一轮视频检索或压缩。

**训练与验证。**缓存策略免训练。原文对层次评分、跨层平滑、位置策略进行分析，在流式和离线视频评测中考察质量与时延；其结果范围不能被解释为任意时长、任意细节都能保存。[HERMES §3.1–3.3、§4](https://arxiv.org/pdf/2601.14724)。

### 3.3 同一路线的演进与差异

ReKV 保留外部历史并检索，StreamMem 在未来问题未知时筛选视觉 KV，MuKV 引入多粒度管理，OmniMem 按模态与扰动敏感性分配缓存。Video-XL 的总结 token 最终承接的是压缩 KV，应放在 T2。MemRoPE 的主要问题是怎样在聚合缓存时保持位置处理一致。

IndexMem 和 RetentiveKV 在 T2 之外加入 T3：精确保留部分 KV，再用关联状态近似补偿淘汰内容。前者学习保留评分并以状态读出补偿注意力；后者采用 SSM 式状态演化。二者是两类构件的组合，而非新的任务分支。

## 4. T3：关联矩阵记忆

### 4.1 总体设计

这条路线用一个映射保存键值关联。读取不再遍历历史条目，而是将查询向量与状态矩阵相乘。为统一维度，下文采用 $S\in\mathbb R^{d_v\times d_k}$、$q,k\in\mathbb R^{d_k}$、$v\in\mathbb R^{d_v}$ 的列向量记号。

1. **生成地址和内容。**将当前隐藏状态投影成记忆查询 $q_t$、键 $k_t$ 和值 $v_t$；地址与内容可以使用不同投影。
2. **从旧状态读取。**$r_t=S_{t-1}q_t$。读出可以加到残差流，也可以调节注意力查询、输出或其他中间计算。
3. **写入关联。**最简单的是衰减加外积；delta-rule 则先预测 $S_{t-1}k_t$，只写入与目标值的误差，减少重复关联的无选择累积。
4. **学习静态规则，运行时更新状态。**投影和门控可通过训练学习；每次实例交互更新的是 $S_t$。这不要求每一步对基础模型做反向传播。

两种常见写入算子的抽象比较：

$$
\begin{aligned}
\text{外积累积：}\quad S_t&=\lambda S_{t-1}+\eta v_tk_t^{\top},\\
\text{误差修正：}\quad S_t&=\lambda S_{t-1}+\eta(v_t-S_{t-1}k_t)k_t^{\top}.
\end{aligned}
$$

这两式是机制示意，具体实现可以使用向量门控、归一化、分头状态和分块更新。VideoLLaMB 虽然也递归，但它传递的是 token，因此仍属于 T1；**递归不是关联矩阵的充分条件。**

### 4.2 代表工作：δ-mem 的“读—调节—写”

**读取。**冻结 Transformer 骨干；新增模块从当前隐藏表示产生低维查询，在旧矩阵中读出 $r_t$。该读出不会返回文本段，也不增加记忆 token。

**调节计算。**两个投影将 $r_t$ 分别变成查询修正和注意力输出修正。前者影响当前 token 关注哪些显式上下文，后者直接补充注意力结果。模块参数固定后，同一个当前输入仍能因旧状态不同产生不同修正。

**写入。**完成当前注意力计算后，依据键值预测误差更新状态。原文采用逐维保留门和写入门：

$$
S_t=\operatorname{Diag}(\lambda_t)S_{t-1}
+\operatorname{Diag}(\beta_t)
\bigl(v_t-S_{t-1}k_t\bigr)k_t^{\top}.
$$

第一项控制保留；第二项沿当前键的方向擦除旧预测并写入目标值。相比单纯 EMA，更新显式使用了“旧记忆对当前关联预测得怎样”这个误差信号。

**训练。**先将上下文写入状态，预测时不把历史文本重新作为显式上下文播放；冻结骨干，以回答交叉熵训练记忆投影和门控。原文将记忆任务与一般能力分别评估。这种设置让损失必须利用状态通道，但仍不能据小矩阵上的平均增益推断任意历史容量。[δ-mem §3.1–3.6、§4–5](https://arxiv.org/html/2605.12357v1)。

### 4.3 同一路线的演进与差异

Metis 将动态矩阵、归一化状态和可学习读写程序嵌入模型；δ-mem 用关联状态调节冻结骨干；IndexMem、RetentiveKV 把关联状态作为显式缓存之外的补偿。共同技术问题是写入干扰、遗忘门、状态归一化和读取地址是否可分离，应用任务只决定训练目标与评测。

## 5. T4：条件查表记忆

### 5.1 总体设计

这条路线显式维护离散键到潜向量的映射，将反复出现的局部模式通过查表提供给模型。与实例库的语义近邻检索不同，地址由预定义离散模式确定，通常不需要扫描或比较全部存储条目。

1. **定义地址。**将局部 token 序列规范化为离散 n-gram，或建立确定性的模式键；决定哪些表项在当前步骤被访问。
2. **构建值。**向量可在预训练中学习，也可由另一个冻结模型离线产生。存储量随表容量增加，而非随当前会话一步步增长。
3. **消歧与融合。**查出的静态向量投影后与当前隐藏状态交互，通过门控抑制哈希碰撞或一词多义带来的噪声。
4. **处理系统开销。**地址确定后可以预取；总表仍可能很大，需要核算 CPU／GPU 存储、带宽和命中率。

$$
a_t=\operatorname{Address}(x_{t-n+1:t}),\qquad
 e_t=E[a_t],\qquad
 h_t'=h_t+g(h_t,e_t)\odot P(e_t).
$$

该式概括查表与融合；学习得到的向量表不等同于逐条保存可追溯的用户经历。

### 5.2 代表工作：Engram 的多头 n-gram 查表

**地址构造。**先规范化 token ID，再为不同 n-gram 阶数使用多组哈希。每个哈希头读取对应 embedding 表，多头结果拼接成记忆向量；多个地址有助于缓解单一哈希冲突。

**上下文门控。**将记忆向量投影为键和值，用当前隐藏状态作为查询计算归一化的门值。相同 n-gram 可以读到相同静态向量，但当前上下文控制其注入强度；后续短因果卷积补充局部融合。

**写入与扩容。**表值在预训练中学习，推理时进行确定性读取，不把新交互自动写成新事实。原文在相同参数与计算预算下比较记忆表和 MoE 的容量分配，说明其研究对象是计算与知识查找的分工。[Engram §2–4](https://arxiv.org/html/2601.07372v2)。

Memory Grafting 沿用条件查表接口，但将值改为冻结模型离线输出的 n-gram 隐藏表示，并引入最长后缀匹配及未命中回退。两者的关键差别是**值怎样构造**，不是一个面向文本、另一个面向 agent。[Memory Grafting](https://arxiv.org/html/2605.20948v1)。

## 6. T5：参数记忆

### 6.1 总体设计

参数记忆将某个上下文产生的条件行为蒸馏进可调用的模型模块。读取时不是额外喂入记忆向量，而是使用修改后的前向映射。

1. **确定写入目标。**将原文、历史或经验转换为训练样本／teacher 分布。目标选择决定写入的是表面文本、可回答事实还是任务行为。
2. **限制可更新参数。**冻结基础模型，只优化小模块，例如 LoRA 的低秩矩阵。每个上下文可使用独立模块，避免把所有内容累积写入同一增量。
3. **构建模块索引。**保留模块与上下文的对应关系。查询时先检索候选，再选出适合当前请求的模块。
4. **控制调用与版本。**决定是否启用、何时失效、怎样更新。只证明模块能拟合上下文，还不足以证明它在非 oracle 检索时安全有效。

对某层权重，可写为：

$$
W_i'=W+A_iB_i,\qquad
A_i\in\mathbb R^{d_{\mathrm{out}}\times r},\quad
B_i\in\mathbb R^{r\times d_{\mathrm{in}}}.
$$

这里 $A_iB_i$ 是学习到的参数增量；它与 T3 中按实例历史递归变化的 $S_t$ 在运算角色和更新协议上不同。

### 6.2 代表工作：Context Distillation 的模块写入、选择与启用

**独立蒸馏。**每个上下文 $c_i$ 训练一个 LoRA。teacher 显式读取 $c_i$ 回答，student 只使用查询及对应模块，通过分布匹配将上下文效应写入参数：

$$
\Delta\theta_i^*=\arg\min_{\Delta\theta_i}
\mathbb E_q\,D_{\mathrm{KL}}\!\left(
 p_\theta(\cdot\mid c_i,q)
\parallel p_{\theta+\Delta\theta_i}(\cdot\mid\mathrm{KV}_{\theta}(q))
\right).
$$

**共享缓存。**teacher 可复用固定上下文缓存；student 则专门按“基础模型计算查询前缀 KV、候选模块接着生成”的方式训练，使模块切换与缓存兼容。这个兼容性来自特定训练设计，并非任意 LoRA 都能直接热切换。

**检索、路由与启停。**先用外部 embedding 取候选模块，再利用首生成 token 的隐藏状态、熵和外部相关度做内部路由；选中后以熵门控决定继续使用模块或退回基础模型。模块相关性与是否应启用是两个判断。

**验证。**原文分开测试怎样存、选哪个、是否启用以及效率；需额外计入逐上下文蒸馏成本、完整模块库和索引。它没有证明能以低成本持续写入视频流。[Context Distillation §3.1–3.3、§4.2–4.6](https://arxiv.org/html/2605.28889v1)。

| 路线 | 早期或基本做法 | 当前文献中的细化 | 真正发生变化的技术变量 |
|---|---|---|---|
| T1 | 池化、聚类、固定查询压缩 | 可重建编码、联合读写训练、条件生成、共享压缩器 | 压缩瓶颈、可见历史、训练目标、输入对齐 |
| T2 | 滑窗、固定淘汰、外部缓存 | 多粒度评分、跨层平滑、摘要 KV、位置重索引 | 缓存布局、层内选择、位置、搬运成本 |
| T3 | 外积累积与衰减 | delta 误差修正、逐维门控、可学习写入程序 | 状态更新方程、地址干扰、归一化、读出位置 |
| T4 | 单一局部模式查表 | 多头哈希、上下文门控、离线大模型构表 | 地址冲突、值的来源、融合算子 |
| T5 | 将多个上下文累积蒸馏进单一模块 | 独立模块、检索路由、启停门控、缓存兼容训练 | 参数隔离、训练成本、模块选择与失效机制 |

这些是本报告对机制差异的归纳，不代表严格的论文继承关系。三个直接有用的组合是：

- **T1＋结构索引：**结构负责身份、时间和关联，潜 token 负责密集内容；HyMEM 已展示类似混合方向，不能把“图＋向量”笼统作为全新空白。
- **T2＋T3：**KV 保存部分较精确内容，矩阵状态补偿淘汰信息；IndexMem 和 RetentiveKV 是已存在的直接参照。
- **T4／T5＋实例记忆：**查表知识或参数模块可提供通用模式，具体发生过什么仍由实例记忆记录。该组合是设计视角，当前材料并未统一证明其在长视频上有效。

颜水成／NUS 的脉络可用同一技术语言解释：MemGen、VisMem（2025 首发补充前作）探索潜 token 生成与视觉读取；L²-VMAS 分离视觉／思考来源；Mem-W 共享观察—动作压缩器；LaMem-VLA 改变 token 注入的使用者；StreamFlow 和 LatentStream 增加流式写入与问题后的 token 演化。**来源、使用者和访问策略改变，但核心 token 接口并未因此成为新的同级类别。**[MemGen](https://arxiv.org/abs/2509.24704)、[VisMem](https://arxiv.org/abs/2511.11007)及其他论文见 §7。NUS 的 Chua／Yang Zhang 合作线和 Wee Sun Lee 团队仍按各自署名区分。

## 9. 设计比较与可验证问题

### 9.1 每类到底要控制哪些变量

| 技术 | 最关键的设计变量 | 能区分设计优劣的检查 |
|---|---|---|
| T1 | token 数、维度、写入感受范围、压缩器与读者是否共同训练 | 同字节预算下的精确事实恢复、直接答与重建后答、读取器迁移 |
| T2 | 每层预算、保留分数、跨层一致性、位置策略、外部缓存大小 | 罕见细节保留、位置扰动、问答到达时延、CPU／GPU 总占用 |
| T3 | 状态维度、读写次序、遗忘／写入门、键归一化 | 关联冲突、矛盾更新、长间隔遗忘、清空状态与禁用读出的消融 |
| T4 | 地址规范化、哈希头、表容量、值的来源、融合门控 | 冲突与未命中、分布迁移、知识任务表现、查表带宽 |
| T5 | 写入样本、更新参数量、模块隔离、检索与启用门 | 单次写入成本、错误模块负迁移、更新／撤销、检索未知时的准确率 |

### 9.2 统一预算，避免比较对象错位

若 $s$ 为每个数值的字节数，可分别估算主要存储项：T1 为 $smd$；T2 为 $2sLH_{\mathrm{kv}}Bd_h$；T3 为 $sPd_vd_k$，另加归一化向量；T4 为所有表项字节之和；T5 为所有可调用参数模块的字节之和。$L$ 是缓存层数，$H_{\mathrm{kv}}$ 是 KV 头数，$B$ 是每层每头保留位置数，$P$ 是状态副本数。不同层、头或模态预算不同时应逐项求和，不能套用相同 $B$。

这些式子只估计对应的记忆对象，不包含全部工作区、普通查询 KV、索引、原始证据或共享模型权重。比较时同时记录写入 FLOPs／时延、实际检索与读取成本，并明确是否允许回看原文或视频。**“固定几个 token”“固定缓存”“固定状态”各自约束的对象不同。**

### 9.3 对当前视频研究的下一步

建议先确定存储接口，再测试写入策略。例如，若选择 T1，应先控制压缩器、读者和总字节数，检查完整证据组能否保留；若选择 T2＋T3，应先证明混合状态在同预算下优于纯 KV，再讨论更复杂的触发或分层。避免同时更换载体、检索器、训练目标与推理骨干，否则难以识别增益来源。
