# 工作记录规范

实验入口见 [实验索引](../experiments/README.md)。每个独立实验用自己的 README 和小型结构化文件保存完整记录；本文件规定记录方法，不承担逐次运行日志。

最近一次全项目文档维护见 [2026-09-17 核查记录](documentation-audit.md)。

## 每次实验需要记录什么

- 目的、范围、依据的方案和状态：计划、运行中、完成、暂停或停用；数量目标是否达成单列。
- 实验 ID、run ID、日期与时区、分支、基础提交；运行时未提交代码用冻结快照及哈希追踪，不补造运行时提交。
- 数据/模型来源与版本、题目清单或抽样规则、协议、提示、依赖及设备；无法确认的字段写明未知。
- 实际命令和输入输出位置，区分只读重放、离线导出与会产生新调用的命令。
- 尝试数、技术失败、排除、待复核及通过数，明确分母；API 用量仅计账本实际返回数据，未知调用费用不按零处理。
- 验证内容与结果、限制、原始证据位置，以及后续是否获准执行。

## 保存与修订

小型配置、清单、摘要、检查结果与必要代码纳入 Git。大产物使用明确的本机绝对路径，并说明所在设备及当前是否可用；其他设备缺少产物时保留历史路径，不能伪造文件或声称已复现。

独立运行分别记录。失败、原始响应、旧判定和旧协议保留；修订使用新文件或带版本的归档，并说明替代关系。哈希清单对应冻结输入；维护文档后的当前文件无需伪装成历史快照。

项目级 `STATUS.md` 仅保留当前任务、状态、权威入口和下一步。会话笔记仅保留决策和结果导航。新增实验更新 [实验索引](../experiments/README.md)，新增或替代方案更新 [方案索引](plan/README.md)。

## 提交前检查

核对状态与统计一致，检查本地文档链接及复现脚本路径；历史本地产物缺失须显式注明。运行与变更相关的离线检查，未运行的检查说明原因。检查 Git 暂存区，排除密钥、大型产物与缓存。提交和推送分开记录；本地提交不等于跨设备交接。
