# EG-VQA 15 小时验证方案：两项核心实验与可选弱监督可学性实验

> 版本：v1.1，2026-09-07，服务于 CVPR 2027 方案筛选。当前资源：**已有 Qwen3-VL-8B 模型、1 张 96GB 显存 GPU、一名主要实施者、15 小时墙钟时间**。本文件规定实验方法和事先登记的验收标准；未运行本文中的模型实验。显存容量不代表推理吞吐，所有时间估计须由开始时的实测校正。
>
> 本轮依次回答：①自然视频是否存在可信的联合证据依赖；②在固定记忆内，组合补取能否改善完整证据读取与回答；③时间允许时，既有 QA 产生的弱标签能否训练出有效的集合排序器。两个核心实验优先于第三项。

## 2. 时间、单卡预算与进入条件

### 2.1 15 小时安排

`T=0` 从目标设备上开始准备本次实验计时，数据下载、必要的依赖适配、模型加载、编码、编写最小 harness、失败重试和人工审核均在范围内。已有 Qwen3-VL-8B 权重的历史准备成本另记，不重新计入 15 h；本轮新发生的耗时全部计入。省下的模型获取时间优先用于数据准备和核心实验，不自动增加样本或启动 E3。

| 时间 | 主要工作 | 到点需要的结果 |
|---|---|---|
| 0–2 h | 现有 Qwen3-VL-8B 加载与接口核验、数据准备、最小 harness、50 次混合 profiling、dev 校准、冻结 manifest | D0 关卡通过，或明确降为工程 smoke |
| 2–6 h | E1 配对干预；GPU 推理期间做可独立进行的人工核查 | 完成 E1 目标样本及初步评分 |
| 6–9.5 h | E2 固定快照四组比较与失败归因 | 完成 R0/R1/R2/R* 配对表；决定是否启动 E3 |
| 9.5–12.5 h | 核心未完成则补齐；满足进入条件时才运行 E3 | 核心记录完整；可选实验完成或注明未启动原因 |
| 12.5–15 h | 剩余审核、按视频 bootstrap、误差案例、验收判定和报告 | 冻结结果与复现清单，停止新增模型任务 |

只假定同一个人能在 GPU 自动运行时审查案例；不假定有第二张卡、额外标注团队或另一名开发者。12.5 h 后不再扩展样本、模型或预算点。

### 2.2 单卡模型与读入配置

- 使用现有的 **Qwen3-VL-8B，全程冻结权重**。官方提供 [Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) 与 [Thinking](https://huggingface.co/Qwen/Qwen3-VL-8B-Thinking) 两种版本；以设备实际资产为准，若两者均已具备则优先 Instruct，便于控制短输出成本。D0 固定模型 ID/本地路径、revision（无法确定时记录权重文件校验清单）、版本类型、processor/chat template、精度或量化配置，以及推理后端和依赖版本。优先复用已有可用环境，eval 开始后不更换 checkpoint 或配置。
- 同一已加载模型处理回答、读取控制和文本判分，分时调用；不再同时加载大型 teacher。文本判分与被评模型相同的偏差通过人工审核披露，不能因此声称是独立评价。
- 检索键使用冻结的图文编码器，参考候选为 [CLIP ViT-B/32](https://huggingface.co/openai/clip-vit-base-patch32)。编码后把存活 capsule 的键与图片保存在快照内；不向 reader 暴露已淘汰条目的特征或描述。
- `batch=1` 起步，确定性解码。Instruct 的初始生成上限为：回答 96 个新 token、控制 96、批量文本 judge 256。若现有模型为 Thinking，生成上限必须包含思考与最终输出；D0 按完整输出是否可解析校准这三类上限并重算耗时，不能只计算最终答案 token，也不能假设提示词能关闭该 checkpoint 的思考。各条件使用相同的角色生成配置，eval 开始前冻结。
- 单次输入加输出上限仍为 8,192 token，图像最多 24 张；预处理采用固定 224×224 letterbox，不做超分或依据金标改变裁剪。使用与 Qwen3-VL-8B checkpoint 匹配的 processor 和 chat template，记录 processor 实际缩放后的尺寸与视觉 token 数，不沿用其他模型的 token 估算。所有版本均须满足该上限与下述累计预算；若输出持续截断，D0 不通过。
- 逐调用统计 processor 产生的实际视觉/文本 token，禁止静默截断。E2 每方法每题累计 token 上限 12,288，包含控制、重复视觉输入、最终回答和所有修复/重试；评分属于离线评估成本，另记账，不能反馈给 reader。
- E2 的 R1/R2 最多 2 次方法调用。错误重试也消耗这 2 次机会与累计预算；用完则记录失败，不能偷偷增加第三次。全局预留的重试预算不放宽单题科学协议。
- 一个模型服务分时占用单卡；峰值设备使用量不超过实测总显存的 90%，包括服务预留。只在 D0 调整并发/预留比例，eval 开始后不改变科学输入。E3 小头优先在 CPU 上训练缓存特征，或暂停 VLM 后短时使用同一张卡。

96GB 是容量约束；不沿用“两张 80GB 并行工作”的排期，也不据此承诺某个每秒 token 数。

### 2.3 调用数账本与耗时准入

以下按正式 eval 的 72 题估算。judge 每次最多处理 4 条独立回答，隐藏方法名/条件标签、随机排列，并逐条按同一 rubric 评分；其实际 token 与耗时同样计费。

| 项目 | 回答/控制调用上限 | 文本 judge 上限 | 合计 |
|---|---:|---:|---:|
| D0/dev 混合 profiling | 包括在同一配额中 | 包括在同一配额中 | 50 |
| E1：每题最多 8 种输入 | 72×8 = 576 | 144 | 720 |
| E2：R0/R*/R1/R2 分别 1/1/2/2 次 | 432 | 72 | 504 |
| 核心预留：合法重试、dev 复核等 | 按剩余额度 | 按剩余额度 | 100 |
| 核心合计 | — | — | **1,374；硬上限 1,400** |
| E3：80 个 QA、每题最多 4 个候选集合 | 320 | 80 | **400** |
| 全轮上限 | — | — | **1,800 次物理模型请求，且不超过 15 h** |

E3 重试从其 400 次上限中扣除，不追加配额。金标时间覆盖计算、向量检索、组合枚举、bootstrap 和缓存重排不调用 VLM。不得把一个包含几十次模型请求的“agent 调用”算作一次。

若所有调用平均 20 s，1,400/1,800 次分别是约 7.78/10.00 GPU h；平均 30 s 时分别约 11.67/15.00 GPU h，后者尚未计入其他工作，必须取消 E3。上述为算账示例，**不是实测速度**。

D0 的 50 次配额可分为 8 个 dev 问题的 Full/Blind/Key/Irrel 共 32 次回答、8 次读取控制、8 次四答案 judge 和 2 次最大输入边界检查；不在此之外另加 50 次 profiling。分别测长包回答、短包控制、文本 judge 的 p50/p75/p95 延迟及峰值显存，之后按以下式子决定还能启动什么：

`预计剩余时间 = Σ(各类未完成调用数 × 该类实测 p75) + 未完成编码/实现时间 + 审核/报告保留时间`。

审核与报告始终至少预留 2 h；还需保留 20% 的预测推理时间作为波动余量。调用数上限、预测时间和真实截止时间三者取最紧约束。不能只看剩余显存或小头训练耗时。

### 2.4 D0：2 小时关卡

必须同时满足：

1. 96GB 卡的实际型号、驱动、可用显存和占用者已记录；现有 Qwen3-VL-8B 的版本、权重与 processor 配套情况已核验，可完成 24 张图的回答、结构化读取控制及文本 judge，最小 harness 能产出一条端到端日志。
2. dev 至少有 4 个可解码视频用于校准；计划 eval 18 个视频中至少 15 个可用，且可形成至少 60 道完整配对问题。解码检查覆盖视频开头、中间、结尾、实际 PTS 与帧率。
3. 50 次 profiling 无未解释的 OOM/静默截断，协议检查通过；按实测速度预计能在 12.5 h 前完成两个核心实验的推理与评分。
4. 在 dev 的 32 条盲化答案上人工核验 judge：严格正确/错误一致率至少 28/32。选择偏差、模糊题和分歧另列；不把自报置信度当成已经校准的概率。
5. 数据、模型、prompt、表示、K、预算、样本顺序与评分规则已写入 resolved config；此后不再根据 eval 结果选参数。

若不满足，先取消 E3。若仍不能满足核心预算，则在查看 eval 预测前，登记一个**缩减版 smoke**：按视频 ID 的固定 hash 顺序选 12 个 eval 视频、48 题，同样完成配对对照。它只支持方向判断，不能标作标准规模验收通过。若最小 harness/模型服务仍未跑通，交付工程阻塞与 dev 现象，科学验收记为 `INCOMPLETE`，不把 15 小时方案视为完成保证。

## 3. 数据、隔离与共同评分

### 3.1 固定数据范围

沿用下载器默认配置：HF `lphuang33/EG-VQA` revision `24379571655174cc80e9c1a1603160e6783c6252`，官方 train 内选取 24 视频/96 QA，seed=17。其中 dev 为 6 视频/24 QA，eval 为 18 视频/72 QA；官方 test 不用于本轮调试。问答类型为 temporal/descriptive，每题原标注含 2–4 段证据。

```bash
python -m pip install -r data/egvqa/requirements.txt
python scripts/download_egvqa.py --output data/downloads/egvqa-pilot
```

单个抽查的官方打包视频只有约 224p/3 fps，不能假设所有视频都有原上传画质。对不足一秒的事件、重复抽到同一帧、时间边界偏差和不可辨细节逐项登记。证据在原标注中存在却未被当前帧表示捕获，应归为前端/数据问题。

同一预定 eval manifest 用于 E1 与 E2，不按照某方法是否答对重新筛选 E2。下载缺失、不可构造有效干预、不可装入预算、解析失败等分别计数；不得静默去掉难题、替换视频或复用 dev 充当 eval。

### 3.2 运行隔离与可复现信息

- writer 只读取视频流和允许的时间/来源字段；所有问题共享同一视频快照。问题顺序改变不能影响快照；每题清空控制消息与模型 KV。
- E2 正常 reader 只能打开当前快照中的图片和键，运行时不挂载原视频、全帧缓存、金标、全历史特征目录。E1 和 R* 是单独的特权诊断进程，不能把它们的文件句柄或内容传入正常 reader。
- 评估器可读取金标，不能改变 snapshot、候选生成或方法输出。E3 弱训练不得读取 `evidence`、`metadata.segments` 或金标边界，连候选生成与负例筛选也不能用。
- 保存原视频 SHA、实际 PTS、前端参数、图像 hash、snapshot hash、问题/候选 ID、模型 revision、prompt hash、解码配置与调用账本。
- 缓存键必须包含完整输入图片/文本、模型/processor/prompt revision、chat template、模型版本类型、精度/量化及解码参数（含思考相关配置与完整生成上限）。只可复用完全相同的请求；不能把 E1 金标选帧包当成 E2 存活记忆包。
- 区分物理计算成本和方法逻辑成本：跨方法缓存可节省本轮 GPU 时间，但方法质量—预算表仍按它实际需要的全部逻辑读取计费，不能因另一个方法预先算过而记成免费。

### 3.3 回答、证据与统计

消费者输出短答案与引用的输入 group/capsule ID；不要求输出长推理链。judge 仅获得问题、参考答案和匿名预测，不获得实验条件或谁是本方法。每条预测输出 `correct / incorrect / uncertain` 及一句核验理由。

主要回答分数 `A∈{0,1}`：结论正确且没有改变含义的遗漏/矛盾取 1，否则取 0。自动 `uncertain` 先记待审；不能复核时，定量主表按未成功计，同时报告比例和排除该类后的敏感性结果。引用合法性、标注段覆盖及人工 grounding 判断分别报告，不用“答案碰巧对”代替证据使用。A 标为本地 judge 的 pilot 指标，不冒充官方评分器结果。

所有方法按相同视频/问题配对；对均值差做 **video-cluster paired bootstrap，2,000 次，seed=43，95% CI**。同视频多题、同题多个干预/训练 pair 不作为独立样本。报告原始正确题数、净增题数和涉及的视频数，避免只报百分点。

下面的数值是预先声明的**内部继续门槛**。跨过门槛且 CI 仍跨 0 时只能记“初步正向、待扩大样本”；要写“统计上支持正效应”，对应预注册主差值的 95% CI 下界还必须大于 0。CI 只反映样本重采样不确定性，不消除 judge 的系统误差；eval 审核发现评分偏差时必须单列，不能用窄 CI 掩盖。小样本未达阈值、尤其 CI 很宽时，不等于否定方法。

## 4. E1：真实多段证据的联合必要性

### 4.1 方法与对照

本实验先隔离“消费者是否需要组合证据”，不训练 writer，也不考察正常检索。金标只用于构造诊断包。

1. 对每题的时间证据合并重叠区间，但不合并仅首尾相接的不同事件；把合并后可辨认的事件组记为 `G1…Gm`。若只剩一个组，或两个组实际上展示同一个事实，则不能计为联合依赖候选。
2. 每组等距选 4 个不同 PTS 的实际帧，组内按时间排列。至少要求 2 个独立事件组；重复帧不能伪装成不同证据。固定前端看不清时标为 `not_visually_resolved`，不事后只给本方法加帧。
3. 从同一视频、该题所有已知证据区间以外选取三个互不相同的干扰组 `I1/I2/D`，每组 4 帧；尽可能匹配视觉类别与时间跨度。采用固定 hash/规则选择，人工核查它们没有直接提供答案或替代证据。干扰组不足或替换后仍保留了关键事件的另一份副本，则该题干预无效。
4. 完整诊断包 `Pfull={G1…Gm,I1,I2}`。每题帧数固定为 `4(m+2)`，最多 24 张；所有有图像的干预保持相同帧数、分辨率和表示。组 ID 不暴露“金标/干扰”身份，提供真实来源时间，替换后按真实时间排序，不伪造时间戳。

| 条件 | 构造 | 每题调用数 |
|---|---|---:|
| Full | `Pfull` | 1 |
| Key-i | 把 `Gi` 的所有帧替换为 `D`，其他内容不变；对每个 i 都做 | m≤4 |
| Irrel-1 / Irrel-2 | 分别把 `I1` / `I2` 替换为同一个 `D` | 2 |
| Blind | 同一问题，无历史图片/标题/字幕/证据描述 | 1 |
| 合计 | 所有有图像条件在单题内匹配；Blind 是先验诊断，不是等计算对照 | ≤8 |

若某题无法形成合格完整包，保留失败原因与原计划分母，不能通过换题补满。人工审计时可以记录额外未知路径，但不能据此重写本次已冻结评测条件。

### 4.2 指标与“确认联合依赖”的定义

在能够构造并完成全部条件的配对题上计算：

- `Δkey(q)=Afull(q)−mean_i Akey-i(q)`。
- `Δirrel(q)=Afull(q)−mean_j Airrel-j(q)`。
- `D(q)=Δkey(q)−Δirrel(q)`；这是预注册主干预差值。
- `Full−Blind`、完整包可答率、关键替换/无关替换各自的掉分率。

一道题只有同时满足下列条件，才计入**人工确认联合依赖数**：

1. Full 正确，Blind 错误，两个 Irrel 均正确。
2. 至少两个不同的 Key-i 变为错误，而非只丢掉同一事件的重复帧。
3. 人工检查确认至少两个组贡献不同必要事实，当前选帧能显示这些事实；没有答案/描述文本泄漏，所选干扰组不是另一条有效路径，标准答案本身没有明显错误。
4. 引用与实际输入相符，掉分不是解析格式变化、上下文截断或来源错误造成。

这是**固定消费者、固定帧表示和已检查替代路径下的操作性证据**，不是证明世界中不存在其他答案路径。自动候选不直接计入确认数；只确认 12 个时就报告 12 个，即使还有未审查候选。

### 4.3 具体验收

| 层次 | 标准规模的判据 | 未达到时 |
|---|---|---|
| 有效完成 | 预定可用 eval 至少 60 题/15 视频；其中完整有效干预至少 36 题、覆盖至少 10 视频；全部条件成对，缺失原因完整 | 记 `INCOMPLETE` 或“数据/表示限制”，不判机制成立/不成立 |
| 消费者/视觉入口合格 | 有效配对题的 Full 准确率 ≥60%，且 Full−Blind ≥15 pp | 先修数据、表示或消费者；不直接否定组合记忆 |
| 值得继续的联合信号 | `mean(D)≥0.15`；人工确认数 ≥`max(12, ceil(0.15×Nplan))`，分布于至少 6 个视频 | 确认数少、D 接近 0 时记有限/不足证据，优先审计原因 |
| 强继续信号 | 上述成立且确认数 ≥`ceil(0.30×Nplan)`；72 题时至少 22 题 | 值得扩大独立自然视频样本，仍不称已证明论文主张 |

`Nplan` 为 eval 开始前登记的全部计划题数，通常 72；不能改成 Full 已答对的子集来提高确认比例。另报以有效配对题为分母的比例供解释。

人工审核优先按固定 hash 顺序检查自动联合候选，最多 24 题，每题约 2–3 分钟；多于 24 的未审查项只列候选。审核顺序不按方法提升幅度排序。时间不足以确认足够案例时，归为证据不足。

## 5. E2：固定记忆内的完整证据取回与补取

### 5.1 同一个合法快照

把视频按时间顺序切为不重叠的 2 s capsule，每个 capsule 含 4 个真实帧、真实 PTS、来源 ID 和归一化图文检索键。区间采用左闭右开，边界帧只归属一个 capsule；末尾不足 2 s 时保留实际时段，缺少 4 个不同帧则带有效 mask 填充，不把填充值计成新证据。像素载荷为 RGB uint8、4×224×224×3=602,112 字节；每槽上限 640 KiB，余量存放键与元数据，全局状态预留 64 KiB。

writer 使用 seed=17 的**在线 reservoir sampling**，每到一个 capsule 才决定保留/替换，不读取问题，也不依赖视频最终长度。默认 `K=64`，总持久预算 `64×655,360+65,536=42,008,576` 字节。只运行一个正式预算点。

每条检索键为有效帧的冻结 image embedding 均值，再做 L2 归一化；问题和缺口语句通过同一图文模型的 text encoder 后归一化。填充帧不参加均值。检索使用余弦相似度，ID 确定性打破平局，不额外生成免费 caption。

若 dev 上几乎没有压缩/检索压力，可在 D0 按预先约定规则改为 K=32：仅当 dev 的标注完整组存活率和 R0 取回率均超过 90% 时切换；K=32 的预算为 21,037,056 字节。决定在 eval 前记录，不根据 eval 的 R* 差距寻找“有效的 K”。

每视频仅一个正式快照；全部方法、该视频所有问题共享。evaluator 可另存完整候选审计副本，正常 reader 无访问权限。索引/元数据/缓存属于预算；源文件和已淘汰图像指针不成为 reader 的免费入口。

### 5.2 四种读取条件

最终 evidence packet 都取至多 6 个 capsule（24 张图），按时间排序，消费者 prompt 完全相同；剩余候选不足时采用共同的确定性规则，并记录实际数量。

| 条件 | 初次读取与控制 | 最终选择 | 方法调用上限 |
|---|---|---|---:|
| R0：一次 top-k | 问题文本与存活键做余弦检索 | 相关性最高的 6 个 | 1 次回答 |
| R1：普通二轮 | 先读与 R2 完全相同的 top-3；VLM 输出一条普通精炼检索语句 | 按新语句取 3 个未读条目，与初次 3 个组成最终包 | 1 次控制＋1 次回答 |
| R2：组合补取 | 先读同一 top-3；VLM 输出最多 2 个缺失事实/关系的检索语句 | 在存活库中搜索一个 3 条目的互补组合，再与初次 3 个合并 | 1 次控制＋1 次回答 |
| R*：标注注入参考 | 独立 evaluator 使用金标时间组，正常 reader 不接触 | 只从**该快照存活条目**中取能覆盖已知组的至多 6 条，余量按 R0 相关性补齐 | 1 次回答 |

R1/R2 的控制输入只含问题与初次 3 个 capsule，不包含完整库的 caption、金标或此前答案。控制输出不作为最终消费者的额外答案提示；最终消费者只接收问题和所选真实图片/时间/ID。两者都固定两阶段，不在本轮训练停止策略；控制器认为“已经足够”时仍执行预登记的补取规则。

R2 的第一版采用可直接实现的规则组合，避免在核心实验中引入训练成本：

1. 对最多两个缺口语句分别检索 top-6 未读条目，合并去重；按两语句的最大相关性截成最多 8 个候选。
2. 枚举其中所有 3 条目组合，最多 `C(8,3)=56` 组，用冻结键计算：`score(S)=sum_j max_{i∈S} cos(key_i, text_j) − 0.2×mean_pairwise_cos(S)`。
3. 选择分数最高组，ID 确定性打破平局；只有一个合法语句时使用一个覆盖项。空/非法输出按固定原问题回退，记录回退，不能调用金标修复。

R1 使用同等长度上限的控制 prompt，随后直接按单语句相关性取 3 条；不使用组合目标。它控制“多调用一次/多读一轮”的收益。R2 相比 R0 的提升不能单独作为组合机制证据，**主比较是 R2−R1**。这种缺口读取受 [REVEAL](https://arxiv.org/abs/2608.08612) 等工作启发，本轮不把一般二轮检索本身当作新颖性证据。

R1/R2 均读取初始 3 条＋最终 6 条，重复输入也收费，累计为最多 36 张图的曝光；R0/R* 为最多 24 张。除共同 token/call 硬上限外，还要求 R1/R2 的平均累计逻辑 token 差不超过 5%，才按等成本主比较解释；超过时报告成本不匹配，不通过该项科学验收。

### 5.3 R*、指标与归因边界

对 E1 规则合并后的每个标注时间组，只有当**同一个 capsule** 中至少有两个不同 PTS 的有效帧落在该组内，才标记该 capsule 覆盖该组；集合只要包含这样的 capsule 就覆盖该组。这一保守定义使每个条目对应一个组覆盖 bitmask。以此计算：

- `Stored_ann`：快照覆盖所有已知时间组。
- `Feasible_ann`：存在至多 6 条的存活集合覆盖所有已知组。可用 m≤4 的 bitmask 动态规划求最小覆盖，额外条目按固定相关性补齐。
- `Access_ann(R)`：方法最终 packet 覆盖所有已知组；同时报告在 `Feasible_ann=1` 上的条件比例。
- 回答正确率 A、引用 ID 合法率；辅报 `J_ann=A×Access_ann×引用合法`。
- 实际逻辑 tokens、调用数、延迟、峰值显存、控制解析/回退率与物理缓存节省。

这些是**标注时间组覆盖代理指标**。长时间段内抽到两帧不保证抽到关键动作，也不保证模型使用了证据；不得把 `J_ann` 写成经过证明的 grounded success。

R* 是一个具体的标注辅助注入参考，可能因帧表示/选包/消费者而失败，**不是数学上界**。它不能取回被 writer 删除的原视频帧，也不能直接使用 E1 的特权选帧包。若无法覆盖全部已知组，则标记不可行；该行仍保留，并用最大覆盖参考包记录诊断输出。

按以下顺序输出失败分布，归因只针对已知路径：

1. 完整候选都缺少关键帧：前端/数据未捕获。
2. 完整候选有时间覆盖、快照没有：已知路径未存活。
3. 快照有覆盖，但 6 条装不下：读取预算不可行。
4. R* 能答对、正常方法没取齐且答错：有已观察到的可修复读取缺口。
5. 已取齐标注覆盖但仍答错，或 R* 也答错：消费者/表示/注入包问题，不能仅凭此区分是哪一种。

### 5.4 具体验收

| 层次 | 标准规模的判据 | 解释 |
|---|---|---|
| 有效完成 | 至少 60 道问题/15 个视频完成四条件的执行或明确终止记录；同快照与隔离检查全通过；预算违规为 0 | 方法解析/推理失败按未成功计，不只保留成功响应；缺条件、越权读回或漏计费用则不通过有效性验收 |
| 有可测的读取空间 | `Feasible_ann` 子集至少 24 题、8 视频；该子集 R*−R1 的 A 差 ≥10 pp，且净增正确题 ≥4 | 差距小则 reader 的贡献空间有限；不是强行改 K/reader 后重测同一 eval |
| 组合补取值得继续 | 全部配对题上 R2−R1 的 A 差 ≥5 pp、净增 ≥4 题且改善涉及 ≥3 个视频；可行子集的 `Access_ann` 差 ≥10 pp；R2 不比 R0 低超过 2 pp | 需要同时看到任务结果和证据取回方向一致 |
| 公平性与 grounding 核验 | R1/R2 token 差 ≤5%；列出所有 R2 正确而 R1 错误的题，按固定 hash 盲审最多 12 题，8–12 题时全部审；≥80% 的被审增益能由新增真实证据解释 | 可审增益少于 8 题时，记正向案例但仍需扩大 grounding 审计；不能强行宣布这一关通过 |

若只发现 R* 与普通读取之间的空间，R2 没有改善，结论应是“存在读取瓶颈，当前补取规则未解决”。如果 R1≈R2 且均优于 R0，则结论是普通二轮读取已能解释主要收益。本轮不据此宣称训练写入 critic、组合 RL 或完整 BundleMem 已有效。

## 6. E3：可选的 QA 弱监督集合可学性

### 6.1 启动条件

只在 E1/E2 已有效完成且已生成主表、科学协议没有未解决缺陷、当前不晚于 9.5 h 时考虑。还须有 E1 的可信联合案例与 E2 的读取空间；至少为弱标签、编码/训练、审核保留预测所需时间，再加 20% 推理余量，并确保 12.5 h 前结束模型任务。E3 数据下载和新增环境准备也算在这一预算内。

条件不满足则写 `NOT_RUN` 并说明原因。弱监督创新性问题留待后续，不以临时训练一个 loss 下降的模型替代可学性证据。

### 6.2 数据与自动偏好标签

可复用下载器的扩展配置取得与 pilot 不重叠的 40 个官方 train 视频/200 QA；下载命令见[数据说明](../../data/egvqa/README.md)。本实验只按 question ID 的固定 hash 顺序取每视频 2 题，共 80 题。

40 个视频在读取任何奖励前，按 seed=29 的视频 hash 分为 **32 个训练视频、8 个留出视频**。留出集不用于选择 epoch、学习率或结构。原 pilot 的 18 个 eval 视频另作为最终缓存重排集，三个来源互不重叠。

每题从同一合法 reservoir 快照构造最多 4 个、每个 6 条的不同集合：

1. 问题相关性 top-6。
2. 从 top-12 中用固定 MMR（相关性权重 0.8、去冗余权重 0.2）取 6 条。
3. top-3 加 3 条固定种子的随机未读条目。
4. 把视频时间轴分成 6 个等长区间，各取最高相关性的存活条目；空区间按剩余相关性补齐。

所有候选都在 query 已知的读取阶段产生；不得读取 `evidence`、源描述、金标时间戳，也不能用答案文本做图文检索。答案只在离线 judge 计算结果标签时使用。集合重复则去重，不靠重复样本凑数量。

冻结消费者对各集合回答。使用已校准的答案 judge，正确集合与错误集合构成同题偏好；`uncertain` 不参加偏好，不能当负例。每题最多 4 个候选意味着最多 6 个无序 pair，但它们共享同一个问题，训练权重按问题归一化，统计按视频聚类。

目标获得至少 120 个有效训练 pair、覆盖至少 20 个训练视频，以及至少 32 个留出 pair、覆盖至少 6 个留出视频。前 10 个训练视频若有效 pair 少于 20 个，停止扩展标签，把“奖励基本打平/无法区分”记为主要结果；不读金标找容易的正负组。

### 6.3 模型与对照

仅使用冻结的 query key 与各 capsule key（可附规范化时间位置），不读答案、judge 分数、gold 描述或候选是否来自某个优胜方法。

- **Additive**：同一个小 MLP 分别给 `(query,item)` 打分，集合分为 item 分数之和。
- **Set**：共享 item 特征变换后做 mean/max pooling，再由小 MLP 输出集合分。它能表达集合上下文，但不预设一定优于加性模型。
- 两者共享样本、特征、优化步骤；实际参数量均约 0.15–0.25M，参数差 ≤10%，否则调整隐藏宽度并在训练前记录。
- Pairwise logistic loss；AdamW，lr=1e-3，weight_decay=1e-4，batch=64，clip=1，固定 20 epochs，seeds=17/29/43。使用最后一个 epoch，不在留出集挑 checkpoint；本轮不做超参数搜索。
- 三个种子、两个小头累计训练时间上限 20 分钟。CPU 可完成则不占 GPU；超时则记录未完成，不把单 seed 包装成三 seed 验证。

### 6.4 留出测试与复用 E2 结果

先测 8 个未见视频上的 pair ranking accuracy，平分记 0.5；报告 Set−Additive、三个 seed 的范围及按视频的 CI。

再在原 pilot eval 上，把 E2 已产生的 **R0/R1/R2 合法最终包**组成固定候选池，去掉重复包；**R* 不进入候选池**。两个小头只根据可见特征选择一个包，由 evaluator 查询其已经缓存的消费者回答和分数，重算最终准确率；不再产生额外 VLM 答案。

这里检验的是“同一个冻结候选池上的集合重排”，不是完整 learned reader 部署。生成这个候选池需要 R1/R2 的两次控制，加上最终一次回答，部署逻辑成本高于 E2 单独的 R2；两个小头按相同候选生成成本比较，并单列该成本，不能把缓存查分的零新增 GPU 时间称作零成本推理。不能用缓存答案/得分作为排序输入，也不能挑完答案后再选集合。

### 6.5 具体验收

| 层次 | 标准 | 未达到时 |
|---|---|---|
| 弱标签合格 | 达到上述训练/留出 pair 与视频下限；人工盲审 20 个训练 pair，至少 18 个方向正确；无金标证据字段进入选样/特征 | 不训练或不解释可学性，先修标签 |
| 可学性信号 | 三 seed 的留出排序准确率中位数 ≥60%，Set−Additive 中位数 ≥5 pp，至少两个 seed 的差值为正 | loss 下降不算通过；若仅优于随机而不优于 Additive，说明尚无集合结构收益 |
| 下游转化信号 | 缓存重排的 A：Set−Additive 中位数 ≥4 pp 且净增 ≥3 题，至少两个 seed 为正；标准规模的 72 题对应至少 3 个净增 | 只有排序收益时记“表示可学，下游转化未验证” |
| 监督表述 | 没有新增人工链标注；人工审计标签只用于质量报告，不回灌训练 | 只能称既有 QA 的弱监督可行性，不能称纯自监督或已经解决在线写入训练 |

若 E3 只有 6–8 个留出视频，CI 很可能很宽；即使跨过继续门槛，也只进入更大样本验证。人工审核与单 seed 异常必须记录，不依据最终 eval 更换候选池或调参。

## 7. 运行前检查、输出文件与最终判定

### 7.1 必须实现的最小科学协议检查

| 检查 | 具体构造 | 通过条件 |
|---|---|---|
| 快照因果性 | 换问题、答案、金标；对相同可见前缀替换未来帧 | 过去 writer 状态/正式快照不受未来问题影响；前缀 hash 不受未来帧影响 |
| 禁止回放 | 关闭原视频和全帧/全特征目录；读取已淘汰 ID | 所有正常 R0/R1/R2 请求只能返回存活载荷；非法 ID 被拒绝 |
| 双预算 | 满槽、超字节；重复读图、解析失败、重试、超 token | 持久预算与每题累计预算均不越界，错误不能绕过账本 |
| 成对干预 | 比较 Full/Key/Irrel 的图像 hash、帧数、PTS、差异位置 | 只有登记的组被替换；其他帧不变，无隐藏关键副本 |
| 跨题隔离 | 改变问题执行顺序，复用同一快照 | 输入快照相同；没有上题消息/KV/反馈进入下题 |
| 评分与聚合 | 插入错误 ID、缺失结果、重复重试记录 | 非法引用与失败被计入；每逻辑条件只算一次，样本分母可重算 |
| 弱监督隔离 | 检查 E3 读取路径与序列化样本 | 不出现 evidence/metadata/gold 时间；同视频不跨训练与留出 |

前六项是两个核心实验的有效性前提；第七项是 E3 前提。只检查下载器不足以通过这些检查。代码未实现或环境不支持时明确写“未运行”。

原始产物放计算设备本地的独立 run 目录，Git 只保存配置、小清单、摘要和实验 README：

### 7.3 最终结论模板

每项实验分别填写：

1. **工程状态**：`COMPLETE / INCOMPLETE / NOT_RUN`；完成比例与未运行原因。
2. **科学有效性**：隔离、预算、公平对照、样本分母和审核是否通过。
3. **研究判断**：`CONTINUE / INCONCLUSIVE / REVISE`；逐条引用门槛和实际计数/CI，不以训练 loss 或单个漂亮案例替代。
4. **下一步**：若 E1/E2 正向，扩大独立样本后再投入 writer/reader 训练；若只发现读取空间，改进检索；若前端看不清，先修表示；若 E3 标签不可靠，先修自动监督。

**整体完成标准是两个核心实验形成有效、可复核的结果，而不是必须得到正结果。** E3 没有启动不会使整体交付失败；E1/E2 在小样本上无显著提升，也不能被写成完整方法已经失效。上述所有模型结果、运行时间和科学验收当前均为待执行。
