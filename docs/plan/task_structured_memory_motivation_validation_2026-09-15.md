# 任务相关记忆结构化存取：动机验证方案

日期：2026-09-15。状态：实验设计，尚未执行。当前目的为验证动机，不启动完整 critic、生成器或投射器训练。

承接[9 月 14 日方案](../../research/2026-09-14/bundlemem_worldmm_relational_sufficiency_proposal.md)。本轮调整：主线收敛到任务相关的证据结构如何共同指导保存与读取；固定回答模型和输入投射。压缩、在线更新与遗忘继续排除。

2026-09-16 用户澄清：本方案中的“结构”指**记忆内容的内部组织关系**——观察按对象、事件过程等内容关联组成可复用记忆块；不指图、文本流或 latent 等表示形式。下面的图和关系模板只是候选实现，不是研究对象的限定。

- 内容关联先于具体查询存在；任务先验可影响组织与保留，具体问题到来后再从这些关联内容中选取证据。
- 对象经历、事件过程等内容块可以重叠、跨时间，不要求等同固定时长切片、语义相似聚类或互斥分区。
- 内容块是可复用的组织单元，不自动等于某题的充分证据组；充分性仍需相对于问题验证，可能需要组合多个块。
- 核心对照应固定底层内容与表示形式，比较按内容关联组织并存取、逐条存取及匹配粒度/大小的普通分块。通用图/无图对照只作实现消融，不能代替这一验证。

**1. 需要验证的三个假设**

- H1（必要性）：自然任务中存在单条相关证据很多、但充分证据组未完整到达回答模型的失败，而且修复后任务表现有可观改善。
- H2（可实现性）：不读取测试问题的写入器，利用自动获得的任务相关证据结构，与读取端共同操作这些结构，可以在同预算下提高充分证据到达率与有证据支持的答题正确率。
- H3（协同价值）：结构同时指导保存与读取的效果，优于单独改进任一阶段；进一步检验共同目标是否优于两个阶段分别优化。

H1 成立不自动证明 H2；H2 成立不自动证明 H3。“结构化”不等同建图，“同时启用”不等同联合学习，“完整时间覆盖”不等同语义充分。

**2. 先利用已有负结果修正测量方式**

仓库[9 月 7 日工程 smoke](../../experiments/EXP-20260907-egvqa-15h-pilot/README.md)已经执行了 12 视频 / 48 QA 的证据干预与组合补取。E1 未检出预定联合信号；其时间证据注入参考即使覆盖全部标注区间，也没有表现为可靠的答案上限。后续[失败审计](../../experiments/EXP-20260907-egvqa-failure-audit/analysis.md)发现评分不一致，且多段标注、视觉可见事实和联合必要性之间不能直接画等号。

这些是其他运行记录中的历史结果，本轮没有重跑或重算，不能当作本机新结果。原始文件、分数和后续修正全部保留，不重新挑选其中“可能成功”的题作为新测试集。

新实验因此先固定三个条件：源证据实际可见、题目确实依赖所标事实、同题同参考同答案使用一致评分。先导阶段不得把失败都归因于弱 VLM，也不得只保留某模型在完整输入下答对的题来估计总体收益。

REVEAL 官方实现可取得时加入；否则依据论文实现的 verifier / gap-driven retrieval 必须称“REVEAL-style adaptation”，不能写作官方复现。主验证不因它的代码入口未确认而停止。

每个主基线保留原生结果和预算适配结果两套。原生结果用于确认接入没有明显失真；因信息范围或资源约束不同，不与预算版本混成同预算排名。各基线内部的对照固定其控制器、工具模型、回答器与输入模板；如另统一回答器，应单列为受控接口实验，不冒称原生性能。

WorldMM 和 Ego-R1 原有图、分层索引及多轮能力均保留。不能先退化为平铺 top-k，再把恢复图结构称为超越强基线。

**4. 共同信息与预算协议**

有限历史 H → 构建候选 → 在具体测试问题公开前选出 M → 冻结 → 对同一 M 回答多个问题。任务族及其权重只能来自训练/开发数据或预先声明的部署先验；测试问题、答案、选项及人工 witness 不得进入实际写入器。每题结束清空查询临时状态，后续题不得获得前题额外记忆。

前端统一固定帧采样、分辨率、事件抽取、源载荷 codec 和检索向量；先在独立开发集验证关键动作可见性。本轮不学习新的压缩器。构建阶段可处理完整有限历史，构建成本单列，不宣称在线常数内存写入。

- Bs：实际持久字节，包含所有可访问源图像/视频载荷、文本、图、向量索引、ID、结构和 metadata。共享来源去重；原视频路径若可回读，其内容必须计费，否则禁用该入口。
- Br：查询总调用与计算限制，覆盖所有查询分解、验证、候选打分、图扩展、视觉工具和重试；记录累计输入/输出 token 与端到端延迟，不只数检索轮数。
- Bi：最终交给回答器的文本与视觉 token 上限。采用同一格式化器，初版不增加学习型投射。

起始预算网格建议：完整固定候选存储的 10%、25%、50%，外加 100% 存储诊断参考；读取低/高两档按原生基线开发 profiling 冻结。选定主工作点应同时存在存储与读取约束，并让一部分人工证据组确实可容纳，不能根据测试结果选最有利预算。

百分比相对于同一候选全集字节，实际字节必须报告。结构 metadata 不能免费；增加一个 metadata 可让基线将同样字节用于其他内容的对照。全预算网格不必立即铺开，先跑一个主工作点，成立后增加两个邻近工作点。

**5. 数据、抽样与证据核验**

自然主数据选 EgoLifeQA 与 Video-MME-long，以共享主基线接入并覆盖跨时段和第三人称视频。EG-VQA 用于辅助证据标注与诊断，不能因其存在多段 timestamp 就自动作为联合必要性数据。[EgoLife 资源](https://github.com/EvolvingLMMs-Lab/EgoLife)、[EG-VQA 说明](https://github.com/HCPLab-SYSU/EG-VQA)。

建议独立开发集约 60 QA；新诊断集约 300 QA：约 200 个按基准分布随机抽样的问题，另约 100 个按人工任务类型选择的结构依赖题。具体名额以可访问数据清单冻结，记录无法获取项，禁止看过方法结果后换样本。两部分分表：随机集估计问题普遍性，富集集识别机制；另报告自然分布加权结果。

重点类型为跨片段时序、身份/交接、状态衔接和跨事件计数；单片段属性/识别作为对照。全视频计数可能需要覆盖全部相关时间与排重，不能仅凭一个小证据组标为完整；无法独立核验范围时单列探索结果。

按原始视频、共享事件与参与者/日期划分开发和测试，关联视角放同一划分。EgoLife 中同一历史衍生的问题不能当成独立视频；正式统计必须披露独立历史/场景数，不能用大量同源 QA 伪造样本量。300 题是先导诊断规模，不保证足以确认 5 pp 的效应。

证据核验记录：必要事实、支持这些事实的实际源帧/片段、关键关系、已知替代路径、无法穷尽项。独立审核者检查事实可见性和答案支持；AI 可辅助提出记录，但不能冒充人工验证。若没有人工核验，结果标为自动 witness 代理，不能宣布科学验证通过。

表示中没有显式关系边但源片段足以恢复关系时，仍算充分；缺少某条已标路径但存在另一条有效路径时，也算充分。无法确定替代路径是否存在的例子不直接判为“不可回答”。

评分优先使用原有选择题标签；grounding 由同一证据规则独立核验。开放答案按同题同参考同预测去重后统一判分，对分歧进行盲审，不允许相同答案在不同方法下获得不同分数。

**6. 实验 A：证明强基线是否存在值得修复的证据缺口**

对两套主基线在同一冻结快照 M 上保存完整检索轨迹，再进行以下查询阶段干预。金标仅用于诊断，不进入可部署 writer。

| 条件 | 操作 | 检验的问题 |
| --- | --- | --- |
| A0 原读取 | 原基线在预算内读取并回答 | 实際参考 |
| A1 已存证据组注入 | 从 M 中选出人工确认充分、Bi 可容纳的证据组，替换原输入；保持固定格式和输入预算 | 证据已存但读不全时，答案是否可以改善 |
| A2 原候选证据组注入 | 从构建前同 codec 候选全集中提供充分组，仍满足输入预算 | 哪些失败涉及没有保存关键来源或关联 |
| A3 关键/无关替换 | 在人工确认的完整包中分别替换必要桥接证据或无关干扰项，匹配长度/数量并核实替代路径 | 答案变化是否由特定证据依赖造成 |

A1/A2 是特权诊断参考，绕过检索搜索，不能称为同成本部署方法；并且不是数学上的性能上界，完整输入也可能使消费者答错。A2 不是合法 pre-query writer，它只能说明候选中有未利用的信息。A0→A1→A2 的差值不是可直接相加的因果故障分解。

A3 必须有无关替换对照，否则删除导致的普遍上下文扰动会被误认作联合必要性。单条证据召回完全相同但完整组不同的配对，仅在存在可核实替代路径且可以匹配时构造；不强行给每题造这样的配对。

记录同时包含“该条件是否可构造”和“构造后答案怎样”，保留全部原始分母。人工可见性筛选与模型答对筛选分开。原候选无法提供完整信息的样本属于前端限制，不能归给保存或检索。

**7. 实验 B：先用不训练新网络的结构策略验证可实现性**

在相同候选与基线原有结构上，增加一个来源可追踪的任务依赖层。初版只处理身份连续/交接、时序及状态衔接三类模板。模板和任务权重在开发集固定；测试时从观察自动匹配，不用测试 QA 或 gold witness。候选中的这些模式只是可能支持任务的组合，不能自动宣布为真实充分组。

W0：原框架的预算适配保存。原框架没有预算 writer 时，提供多样性、事件覆盖和任务相关的单条评分等强对照，在开发集选定最佳者；这些适配必须明确标注。R0：保留原强基线的多轮/图/工具读取。

W1：按任务依赖模板提出小组，组内的实体—事件—来源引用闭合，按任务族权重与新增字节选择组合。可用有限 beam，允许同时加入几条互补内容；所有共享来源去重。初版不训练 critic，使用可解释的模式覆盖分数，其失败只否定该实现，不能单独否定研究动机。

R1：在原检索候选上，按当前问题的关系需求扩展已保存的桥接来源，使用集合 rerank；同一组证据的端点和支持观察一起考虑。原基线获得相同总调用与计算额度，不以增加搜索次数制造优势。

| 条件 | 保存 | 读取 | 对应解释 |
| --- | --- | --- | --- |
| B00 | W0 | R0 | 强预算基线 |
| B10 | W1 | R0 | 结构指导保存的增量 |
| B01 | W0 | R1 | 结构指导读取的增量 |
| B11 | W1 | R1 | 共享任务结构同时用于存取 |

输出仍由原冻结回答器与同一输入模板生成，不能向 B11 额外提供推导答案、gold relation 或更密集图像。结构抽取使用同一观察前端并在所有比较中公开其可用信息；所有新增费用入账。

必须加两个对照：同样候选小组、同样字节/计算，但仅按一般实体/时间邻接组织的“通用结构”；以及保留所有事实不变、只对新增路由/分组信息打乱的控制。打乱可约束度数、组大小和时间跨度，避免仅由明显异常拓扑解释退化；它是结构相关性的辅助诊断，仍可能有分布外影响，不能单独当作主证明。

如果任务结构相对通用结构没有增益，只能支持一般结构化，不能支持任务相关结构的独立价值。如果 B11 仅超过 B00 而未超过 B10/B01，不能宣称联合是必要的。

**8. 实验 C：独立优化与共同目标应另行比较**

B11 只能证明同时使用结构的效果，不能称为联合训练。若实验 A/B 通过，再用同样 W1、R1 模块与相同开发数据作目标对照：

- 分阶段目标：writer 按已存 witness 覆盖调参；reader 在冻结 writer 的快照上按完整组取回调参。
- 共同目标：writer 的选择规则显式考虑固定读取过程能否返回候选组，以最终完整组到达率和 grounded correctness 选择配置。

首版可用有限配置搜索或预先固定的近似 reader rollout，不需要强化学习；开发总试验次数与标签预算相同。配置冻结后，在独立测试历史上构建记忆，writer 仍看不到实际问题。需要生成假想问题时，只能从训练任务模板和当前可见观察生成，并记录调用和构建成本；实际测试 QA 不得参与。之后才决定是否把该过程蒸馏成选择器＋critic。

报告 B11 的交互量 (J11−J10)−(J01−J00) 及置信区间，但正交互不是联合设计的理论必要条件。共同目标优于分阶段目标、且成本相同，是支持“联合优化有价值”的更直接证据。

**9. 指标、统计与继续条件**

主机制指标采用“至少一组经核验的充分证据到达率”：

\[
D=\frac{1}{N}\sum_q \mathbb 1[\exists E\in\mathcal E_q:\ E\text{ 可由最终返回内容恢复}].
\]

N 是预先登记的样本分母。自然 witness 未穷尽时，称“已核验充分组到达率”，并对未匹配但答对的样本复核替代路径；不把 absence of annotation 当作 absence of evidence。

同时报告存储充分组覆盖率 S、存活且输入预算可行条件下的完整组取回率、item recall、原 benchmark 正确率 A，以及已核验组到达且答案正确的联合比例 J。A 不能被 J 取代，J 也不能被引用 ID 合法性取代。对多轮读取追踪全部合法信息来源，避免最终 source 列表漏计中间获得的内容。

在每个预算点报告完整资源账本。主比较是 B11−B00、B11−B10、B11−B01，以及任务结构−通用结构。以视频/相关历史为簇做配对 bootstrap，报告置信区间与有效簇数；多个主要比较采用预先声明的校正。开发后根据配对差异率和聚类程度估算正式样本量，不用 300 题承诺统计显著。

可将主随机集 grounded correctness 增加约 5 pp 设为开发阶段的投入参考，同时要求充分组到达率提高、两个主平台方向一致、单事件对照没有明显退化，并在至少两个邻近预算点维持趋势。5 pp 是建议的最小有用效应，不是已经测得的结果或必须人为达到的阈值。

| 实际观察 | 合理决策 |
| --- | --- |
| 人工充分包也不能使固定模型稳定回答，或源事实不可见 | 先解决前端/消费者/评测，当前设置无法有效验证动机 |
| A1/A2 有明显改善，但自动结构策略无改善 | 动机有待继续，当前结构抽取或选择近似未能利用空间 |
| B01 已实现全部收益，B11 无额外收益 | 证据支持读取改进，暂不支持存取联合主张 |
| B11 提升 D 但不提升 A/J | 存取机制有效但未兑现任务收益；不宣称题目中的完整因果链已成立 |
| 只有 gold 结构、特权写入或更多资源时有效 | 不能支持可部署的任务结构化存取主张 |
| 两个强基线、多个任务/预算均稳定提升 D 与 A/J | 值得进入选择器＋critic 的方法研发 |

自动方法的零收益若置信区间仍很宽应判不确定；只有足够精度排除有用效应、同时 oracle 修复空间也小，才是当前任务上动机较弱的证据。

**10. 最小执行顺序与交付**

1. 约 2–3 天做可运行性与测量校准：WorldMM 原生/预算适配小样本、第二基线最小入口、前端可见性、评分与完整费用。实际耗时取决于权重、数据和 GPU 获取，尚未实测。
2. 先做约 60 题开发核验，冻结数据/预算/规则；再对新诊断集执行实验 A。优先确认自然随机集里的缺口规模。
3. A 打开足够空间后，先在 WorldMM 跑一个预算点的四格及通用结构对照，再移植到 Ego-R1；成立后才扩大预算网格和实验 C。
4. 最终交付三张表：强基线故障及 oracle 修复；存取四格与通用结构；质量—成本及类别/预算结果。每个数字关联冻结记录、证据审计与调用账本。
