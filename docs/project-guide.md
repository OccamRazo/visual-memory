# 项目约定

研究范围与当前决策以 [项目状态](STATUS.md) 和 [执行方案索引](plan/README.md) 为入口。这里说明项目材料如何组织，不替代各实验的协议。

## 目录与权威记录

| 位置 | 内容与使用方式 |
|---|---|
| `research/` | 文献调研、研究判断与方法提案；入口为 [调研索引](../research/README.md) |
| `docs/plan/` | 实施与验证方案，明确当前、历史或备选状态 |
| `experiments/EXP-YYYYMMDD-<name>/` | 独立实验；README 连接协议、代码、结果与本地产物 |
| `writing/` | 论文、图表与周报；草稿中的拟议结果不得当作实测结论 |
| `notes/sessions/` | 以精确会话 ID 命名的简短决策和导航，不复制完整结果 |
| `src/`、`scripts/`、`tests/` | 仅在明确选定持续维护的实现后创建；当前没有正式实现 |

一次性代码、提示和专用依赖放在对应实验的 `code/`。旧 EG-VQA 实现已[归档停用](../experiments/EXP-20260907-egvqa-15h-pilot/code/README.md)。文档沿用已有名称；日期与版本写在正文，不为统一风格重命名历史文件。

## 数据与证据口径

- 原始数据只读。记录数据版本、视频/问题 ID、源文件校验和及实际模型标识；未知版本明确标注。
- 问题、评分事实、任务标签、定位 caption 与原始证据分开保存。caption 是定位索引，不自动构成原始视觉证据。
- 证据组按连续事件或独立章节定义；帧数、离散时间点数、固定窗口数均不等于独立证据组数。
- 区分处理尝试、技术失败、API 候选通过、逐题源复核确认及人工金标。AI 复核不得标成人工审核；源充分性不以回答是否正确替代。
- 改写题目、修订评分或证据边界时保留旧结果与理由。新结果必须重新绑定核验和哈希，不继承旧版本准入。
- 接触过的问题或视频按实验的排除清单管理，不能重新宣称为未见测试样本。

## 产物与暂停

记录要求见 [工作记录规范](work-records.md)。视频、原帧、完整调用日志、模型权重与缓存留在产生设备的忽略目录；Git 保存小型记录、代码与复现输入。凭据放在被忽略的本地位置，禁止写入文档、日志或提交。

暂停实验时停止调度并检查相关进程，记录时间、数量口径、失败、未完成目标和产物路径；必要时保存暂停标记。暂停后的入口不得继续描述为运行中；恢复需要用户明确指示，不因待办或旧命令自动启动。
