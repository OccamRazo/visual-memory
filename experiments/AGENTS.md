# Experiments Directory

These rules apply to `experiments/` and its subdirectories, supplementing the repository-root `AGENTS.md`.

- Store experiment records, reproduction inputs, concise results, and audits here. Keep literature surveys and research proposals in `research/`, execution plans in `docs/plan/`, paper drafts and presentations in `writing/`, and session notes in `notes/sessions/`. Link to those materials instead of duplicating them.
- Organize independent experiments under descriptive `EXP-YYYYMMDD-<short-name>/` directories, using the experiment's actual start date. Preserve existing directory names and create directories only when needed. Keep independent runs separately identified within an experiment; give a follow-up audit its own experiment directory when it has a distinct protocol and results, and link the source experiment.
- Use each experiment's `README.md` as its entry point. Record its purpose, status, source plan, code revision, data and model versions, relevant environment, reproduction commands, result locations, conclusions, and limitations. Identify unknown or unavailable information explicitly; historical device paths do not imply that artifacts exist on the current device.
- Keep one-off validation code, scripts, tests, and dedicated dependency files under the owning experiment's `code/` directory. Do not place them in the repository-root implementation directories or introduce their dependencies as project-wide requirements. Promote code to the maintained implementation only when it is explicitly selected for continued development.
- Mark retired implementations clearly in their entry points and link the retained results and audits. Preserve their source revision and original layout or provide a path mapping and historical checkout instructions. Do not treat archived code as the default basis for new development.
- Commit small records and necessary reproduction inputs. Keep videos, model weights, raw frames, full logs, caches, and other large generated artifacts on the producing device in ignored locations. Check ignore coverage when adding output paths; do not assume rules for repository-root data directories also cover nested experiment directories.
- Preserve frozen configurations, manifests, checksums, original results, and failed runs. Save corrections, re-evaluations, and replacement runs separately, explaining their relationship to the original evidence. Do not rewrite recorded paths or hashes merely to make a historical run fit a new directory layout.
- Distinguish planned work, completed runs, verified findings, interpretations, and unresolved hypotheses. Report sample counts, exclusions, failures, and evaluation limitations with results. Attribute checks to the device and run that performed them; use `not run` with a reason for unavailable checks, and do not present historical checks as newly executed.
- Update affected entry points and local links when adding, moving, retiring, or superseding materials. Preserve external citations and links to historical Git revisions. Check navigation, script paths, and relevant migration invariants after moves; use the smallest verifiable change and preserve unrelated work.
